## Implemented boundary

`createNativeStudyHost` discriminates `generation-supplied-study-v2` from retained-source v1. V1 execution validation, retained input kinds and preparation refusals remain unchanged. V2 consumes an exact, server-owned review row bound to the authenticated principal snapshot, private references/bytes, declared agent author, approved protocol, expiry, candidate, packet, runtime, configuration and full inventory. Private custody uses `supplied-study-source` and `agent-authored-study-direction`; agent proposals never receive provider-response ancestry. It preserves personal/principal, project and Memory exclusions.

`retainSuppliedStudyInputs` is a local trusted intake function, with no route. It authenticates through existing components, requires the already stored study/review and both exact financial grants, and atomically writes only the two exact private copies. It never creates approval, study or financial authority. Synthetic tests explicitly seed fictional records; these are neither real approval nor billing evidence. Hashes and a client review flag do not authorize intake or execution.

The optional SQL extension runs only after the v1 optional schema in an empty disposable fixture; it refuses existing grants or purchases before DDL. V1's exact schema contract is unchanged and rejects the v2 schema. A v2 host requires the separate exact v2 contract. This is local versioning, not a production migration or installed schema.

Each arm has distinct advisory, exact moderation and image POST slots, plus private storage. Advisory uses the ordinary `sourceAdvisoryInputs` serializer and strict positional response validator: two input strings, one POST. The exact check remains one typed text item, one POST. No planner/checker/evaluator, reference, stream, retry or retrieval purchase is introduced. Two arms, six POSTs, two images, concurrency one. Only I's opening replacement changes the prompt. Ordinary compiler parity and exact intercepted request bodies are tested.

The same canonical database batch reserves native token/cost/lifecycle budgets and records the operation. A unique, immutable stage intent precedes each fetch; process loss never replays it. Treatment admission checks the original completed operation, nine complete private evidence slots, a current human observation tied to artifact/receipt/protocol/principal, and the existing lifecycle and financial gates. An expected failure must name a prespecified rubric item. Missing/unknown safety or unclassified fidelity remains paused; no mock judgment is generated by the host. Safety/error/custody failures and explicit stop latch a durable stop. This implementation is conservative: an explicit reconciliation hold also latches the pair, so resolving accounting later does not implicitly resume that stopped packet. Financial settlement/recovery remains possible; a new explicitly reviewed packet is required to reconsider a stopped pair.

Evidence comprises the sealed plan and request/response records for advisory, exact moderation, image and storage: exactly nine writes per arm, at most 2 MiB total, a 16 MiB artifact and two original artifact reads. Recovery checks every named slot and digest. Expiry cleanup attempts object deletion once and removes expired evidence and eligible supplied copies, preserving source-free financial reservations/receipts/holds. Cleanup failure is not retried automatically; no scheduler or funded physical deletion service is supplied here.
