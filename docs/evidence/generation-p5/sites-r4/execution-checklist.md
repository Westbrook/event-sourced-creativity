# P5 execution checklist — only after the decision is actually complete

Use this with the unchanged [R3 runbook](../sites-r3/runbook.md). P5 remains the executor and custodian. Do not ask again for unchanged actions actually authorized in the completed decision. No framework or scheduler is added.

1. **Authority and pins.** Record the accepted R4 decision, economic basis and concrete retention owner/duration/disposition. Check expiry, current sealed hashes and unresolved feedback. If a promised hard deletion deadline is not supported, do not begin. Read fresh native target/version/environment/access/catalog/tombstone receipts. Require the selected existing private target, original v1 lineage, no unexpected credentials or bindings, old migration/snapshot unchanged and disabled N10H. Drift stops this release for reconciliation; do not reopen target selection or widen audience.
2. **One source and version.** After authority only, obtain the ordinary short-lived target source credential; never log/persist its token or request automatic publish-on-push. Reconcile existing publication windows. Use a separate target checkout, preserve historical lineage, overlay only the sealed 19-file standalone source and record a manifest comparison. Do not push the Forma repository. Bind the resulting native commit to the reviewed source tree and nine payload hashes. Stop and reseal any source/Worker/schema/content change. Compression-only equivalence requires a digest plus nine-byte-comparison receipt, not a source reseal.
3. **Admission, then private deployment.** Push the exact reviewed source; use `save_site_version` with the exact matching commit and prebuilt archive; preserve its native admission/archive-storage/version receipt. Only on success call `deploy_private_site_version` with its returned version ID. No remote-build fallback, validation bypass or public deployment fallback. Capture final deployment, env, migration boundary and MEDIA provisioning receipts. A refusal/failure may leave saved source/history or partially provisioned resources: preserve the boundary, stop, and keep custody/cleanup obligations rather than automatically retrying.
4. **One request ledger.** Before the first authorized remote operation create a simple append-only local receipt table: `sequence | UTC | action/index | attempt | issued HTTP count | cumulative HTTP | cleanup attempt | outcome/uncertain | receipt path`. No credentials or payload secrets. Persist counters **before** issuing requests. Count all operator/driver-issued HTTP requests, including navigation/assets, negative probes, each concurrent request, failed/timed-out requests, redirects, status and recovery. Disable automatic retries, polling, reload and prefetch; enumerate any needed asset traffic. For transport with multiple HTTP exchanges (such as Git), account for each exchange without recording authorization headers. Native connector control operations also get receipt rows; reserve request capacity conservatively and never claim their opaque platform-internal traffic is a measured Worker request count. If operator-issued traffic cannot be accounted for, stop before further requests instead of assuming zero. The bound is on the operator/driver, not independent visitor traffic or provider-internal work.
5. **Reserve recovery capacity.** At most **80 total operator/driver HTTP requests** across the authorized attempt, including preflight/status/recovery; count uncertain sends as issued. Reserve the final **12** for one stop, at most five original cleanup attempts, at most five corresponding status checks, and one final verification. Stop admitting normal work once cumulative count reaches **68**, or earlier on any unexpected result/quota/refusal. Reserve both slots before the prescribed concurrent pair. Never reset either counter after interruption, a new process or a native failure. Resume only from the saved ledger. If the ledger is lost, freeze execution and preserve the obligation; do not guess remaining capacity.
6. **Finite fixture.** Confirm ordinary signed-in owner ingress (no bypass token or forged identity). Send start once; ten ordered claimed steps use exactly the compiled two-object fixture and sealed R3 cases. Index 1's two concurrent requests and the specified denied duplicate after index 2 are the already-reviewed probes, not retry permission. New steps end within one hour and before October 1, 2026 00:00 UTC. Capture receipts immediately; cleanup discards the Worker report. Local 842 binding calls and 3,276 SQL statements are distinct observations and establish no managed fit.
7. **Refusal and uncertain state.** Native quota/refusal or any unexpected outcome ends generation/step work. Preserve the exact error, cursor and original intent; do not change SQL guards, request limits, fixture, timestamps or import claim. Use remaining reserved capacity for one best-effort stop and only the original cleanup when safe. A busy phase may require waiting until the original one-hour window ends; waiting is not polling. Lost acknowledgements get bounded status reconciliation, never blind start/step replay. Native control failure is not permission to repeat deployment, migrate again or reactivate N10H.
8. **Cleanup ceiling.** Increment cleanup count before each attempt; maximum **five** across the whole run. Each attempt only checks/hash-verifies/deletes/reads-null the same two original keys and deletes the original synthetic private bodies. Retry only after a specific receipt establishes that same idempotent cleanup is still needed and safe; no blind retry. Never start an attempt if its request would exceed 80. At the fifth attempt or 80th request, issue no further request under this authority. Preserve unresolved custody and escalate the concrete failure; the obligation remains, but the exhausted limit grants no additional action.
9. **Close the attempt, keep P5 open.** Verify disabled P5/report null, old N10H unchanged, both original keys read-null, no synthetic private bodies, and the exact residue inventory. Capture final receipts separately from the Worker report. Do not equate logical read-null with erasure of backups/history. Record the accepted residue owner/duration/end disposition and any unfinished cleanup. No scheduler, timed deletion, teardown or additional retention acceptance is implied. Actual Forma and paid-run gates remain separate.

Retained footprint after successful cleanup: 62 synthetic application rows plus two disabled tombstones; 172 explicit schema objects; local allocated DB 1,060,864 bytes (not a hosted size guarantee); empty MEDIA resource; synthetic fixture/terms/image bytes in source/version history. Runtime stop and proposal expiry do not erase this footprint or establish zero cost.
