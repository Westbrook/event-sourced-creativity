# Still creation provider and search adapter contract

Implementation: v19. The creation rollout remains off by default. These bindings are deployment configuration contracts, not proof of provider qualification. This implementation task did not provision or call paid providers.

| Binding | Meaning |
| --- | --- |
| `STILL_UNIFIED_CREATION_ENABLED` | `true` or `1` admits the dedicated feature routes. |
| `STILL_CREATION_SEARCH` | Worker service binding implementing an independent learned semantic index. |
| `STILL_CREATION_SEARCH_MODEL` | Exact learned representation/model version expected in adapter acknowledgements. |
| `STILL_CREATION_ORGANIZER` | Worker service binding returning source-grounded CreationPlan proposals. |
| `STILL_CREATION_ORGANIZER_MODEL` | Exact organizer model version bound to retained interpretation. |
| `STILL_CREATION_PROVIDER_CUSTODIES` | JSON array of server-approved exact custody keys, such as `personal:<actor>` or `project:<organization>:<access>`. Default is no provider transmission. No wildcard is supported. |
| `STILL_CREATION_JEV_ENABLED` | `true` enables bounded existing Jev assessment when `JEV_API_KEY` is configured and custody permits it. |

The independent lexical index is a D1 token-posting table whose exact lexical terms are hashed. These hashes are not vectors and are never represented as semantic retrieval. Plain source text is held only in protected `creation-search-source` payloads, excluded from generic hydration. Manifests contain canonical IDs, exact revisions/hashes, custody and protected pointers; repeated Document uses are location metadata on one canonical Idea.

`POST https://creation-search.internal/query` receives `{schemaVersion:1,representation:"learned-semantic",modelVersion,partition,query,limit:20}`. It receives no lexical candidates. Return `{representation:"learned-semantic",modelVersion,hits:[{id,projectId,custody,kind,revision,contentHash,rank}]}`. Partition identity includes Project, custody, permission epoch, content/index version and provider policy. The adapter must physically or logically enforce that partition and must not broaden it. Worker filters returned IDs through current manifests, tombstones and fresh authorization before protected hydration or reranking.

`POST https://creation-search.internal/upsert` receives `{schemaVersion:1,representation:"learned-semantic",modelVersion,partition,source}` from bounded background indexing. `source` contains one canonical ID, kind, exact revision/hash, title, readable body and authorized location metadata. Return `{representation:"learned-semantic",modelVersion,id,revision}` only after that exact revision is searchable. Acknowledgements advance semantic coverage; missing/failed acknowledgements do not. Source invalidation immediately makes local manifests inaccessible even if a remote vector still exists. Provider retention and erasure of obsolete vectors must be qualified with the backend before rollout.

`POST https://creation-organizer.internal/interpret` receives the acknowledged draft, explicit selected sources, the accepted decision ledger, organization instructions, model version and an `operationIdentity`. Return `{operationIdentity,plan}` using `src/model/creation.ts`. Scope, source text, draft revision, model version and decisions must match exactly. Source evidence and graph validity are checked deterministically. Incomplete Ideas enter review; invalid IDs, cross-Project evidence, malformed bodies and unsupported relationships fail without creative writes. The adapter returns proposals only and cannot authorize or emit events.

Search obtains up to 20 lexical and 20 semantic candidates independently per authorized partition, merges all pools by relevance before its global 24-candidate hydration budget, reranks separately per custody, and returns up to three. Full candidate pools disclose bounded coverage. New Project discovery is Open-only. No good match is valid. Missing indexing, provider failure, unsupported partitions and account bounds are explicit partial/degraded states, never a conclusive no-match. An aggregate request admits at most 64 Project partitions and discloses larger account coverage as partial.

The query route never replays history. It schedules resumable background pages of 32 canonical records, up to eight pages/20 seconds per background continuation, independently of typing completion. Durable jobs and protected staging pages survive interrupted work; native scheduled continuation renews expiry and resumes without another typing request. History is folded once per invalidated build rather than once per page. The scheduled principal is reauthorized from canonical policy and fails closed where an observed authentication context is required. Canonical event/private-body/resource mutations invalidate manifests transactionally. Old source snapshots and stale provider IDs cannot supply previews while refresh is pending. Source version checks and current actor authorization are repeated before provider indexing and result exposure.

Still requires live qualification of a configured learned backend, source/index coverage, provider retention/custody isolation, source-grounded organizer fidelity, and latency after debounce at 1,000 and 10,000 Ideas. The fixed corpus contains held-out cases, but mocked retrieval/reranking results do not satisfy those gates. No provider configuration in this document authorizes deployment or spending.

## Executable provider service

`worker/creation-provider-service.ts` now implements both service bindings. `workers/creation-provider/index.ts` is its Worker entry, with a default-disabled, private-only `wrangler.example.jsonc`. This is executable source, not an interface to a hypothetical service. The local tests exercise the actual handler against SQLite manifests and injected inference/vector providers; they make no live calls.

The implementation uses native Cloudflare Workers AI BGE embeddings and Vectorize, plus Llama JSON-schema organization. The example uses the documented 1,024-dimensional BGE large model. Embedding passages remain intact across UTF-8 chunks, and their learned vectors are pooled into one canonical source vector. This is independent of lexical postings. The initial English model and pooling must pass the multilingual/long-input corpus before release; the example is an engineering default, not a measured model recommendation. [Cloudflare BGE model documentation](https://developers.cloudflare.com/workers-ai/models/bge-large-en-v1.5/)

The organizer uses the documented Workers AI structured JSON response format; deterministic Worker validation remains necessary because model adherence is not guaranteed. Immutable scope, draft/source identity and accepted decisions are copied from the retained request, not model output. [Cloudflare JSON mode](https://developers.cloudflare.com/workers-ai/features/json-mode/)

Configure both app service bindings to this Worker. Its `CREATION_PROVIDER_TOKEN` secret must match the app's `STILL_CREATION_PROVIDER_TOKEN`; tokens require at least 24 characters and are never placed in the example or logs. The service has its own exact `CREATION_PROVIDER_CUSTODIES` allowlist, separate from the app's allowlist. `workers_dev`, preview URLs and public routes remain disabled. Inference is disabled until `CREATION_PROVIDER_ENABLED=true`. No credential was created or reused by this implementation task.

The service needs a 1,024-dimensional cosine Vectorize index with a **string metadata index named `sourceKey`**, a D1 `STATE` binding, and an `AI` binding. Its embedding and organizer version labels must exactly match the app bindings. Vector metadata contains only source IDs/kind, Project/custody, revision/hash, model version and a hashed source key. It contains no title, body, excerpt, original draft or provenance text. Native provider model names are pinned in the example; changing a model/pooling contract requires a new representation version and qualified index.

`upsert` additionally receives the protected source's exact `expiresAt`. Local service manifests stop exposing expired records. As Vectorize writes are asynchronous, the service returns `202 indexing` until both exact vector readback and a filtered search return the submitted revision/hash. Only then does the app advance semantic coverage. A receipt alone is insufficient. Two-minute recovery leases allow interrupted preparation or never-visible submissions to retry. Revision/hash/claim-epoch-specific vector IDs and the current-source pointer prevent an older slow embedding from overwriting or acknowledging newer content. [Cloudflare Vectorize client API](https://developers.cloudflare.com/vectorize/reference/client-api/)

An authenticated `/delete` request accepts the same partition/model envelope plus up to 64 source IDs. It tombstones only sources at or before that index epoch before deleting their vectors; stale deletes cannot remove newer sources, and same-epoch retries cannot resurrect a tombstone. These are executable lifecycle primitives. The executable scheduled expiry sweep tombstones expired records and deletes lease-specific vectors. Physical deletion of asynchronous remote mutations, crash-created orphan vectors, namespace erasure and expiry scheduling still require an operational lifecycle witness before activation; no cleanup scheduler was deployed or enabled in this task.

The service enforces a streamed 1,000,000-byte request ceiling and at most 16 batches of eight embedding chunks per source/query request. Sources beyond that bound remain explicitly incompletely indexed; they are not truncated. This is an additional provider capacity gate, not a reduced creative draft limit. The fixed initial model/input budget must be enlarged or a different qualified adapter selected if representative long sources exceed it. The main autosave and manual review paths remain available.

Verification: `tests/creation-provider-service.test.mjs` covers executable upsert/query/organize behavior, namespace isolation, no source text in vector metadata, async visibility acknowledgement, interrupted lease recovery, concurrent old/new revisions, deletion during readback, epoch monotonicity and same-revision lease races. Tests use injected providers. A local ESM bundle of the Worker succeeded; no service provisioning, deployment, network inference or paid qualification occurred.
