# Dormant native guest Image source

This increment makes one real native Image source from an explicitly authorized guest session. It does not activate anonymous entry, generation or account adoption. The session/claim ledger alone cannot authorize storage: a separately persisted, reviewed source policy must bind the exact immutable session policy/terms, approved Image release, maximum draft/event bytes, maximum event count and draft lifetime. There are no launch values or policy defaults. The seven-day validation maximum is a technical ceiling, not acceptance of a seven-day guest retention policy.

`prepareGuestImageSource` requires both purpose-separated guest proofs and the exact approved origin. It accepts the server-owned session intent, actual registered Image release and native context-block field provenance. Reference assets and other output shapes are refused. The real `validateIntakeRequest` and `buildExperiencePlan` produce the draft, Project, Document, blocks and native client event identities. The reserved Project/Document IDs must already equal the native compiler's identities; historical random-ID sessions fail without migration. A native `experience-draft` private body stores the unchanged plan. Immutable source receipts contain identifiers, digests, counts and expiry, not creative text.

The shared private-content change permits an explicit expiry ceiling for `experience-draft` only when a valid fixed draft identity and current SQL guard are supplied. It caps at the earlier native retention limit and supplied ceiling, validates nonempty well-formed UTF-8 content at no more than 65,536 bytes, and rechecks database identity and the deadline after asynchronous native policy/cleanup reads. Ordinary callers and other kinds keep their existing behavior. The guest source's transaction also asserts the current session/policies, exact body/expiry and original stream/custody. It never extends tighter native retention.

`commitGuestImageSource` commits the unchanged stored native plan once. The existing native event writer produces the actual public event envelopes, erasable private payloads and native client receipts in one atomic batch with a source-commit receipt. The original actor is explicitly the guest subject; no `PilotUser`, trusted identity header or account row is invented. Final reads verify the complete original event set, private and public payloads, exact owner/Project/Document, actor, sequence and native correlation fields. Its `status: complete` means that source commit completed; every result explicitly says `custodyTransferred: false`.

Exact retries preserve original IDs, content and expiry. A changed request cannot replace the source under the same session. Concurrent calls and a lost database acknowledgement recover the actual original receipt. Session/overall policy expiry or revocation removes usable guest authority. Revocation of only new source storage prevents a first commit while allowing current guest reads and completed-source replay until the original lifetime ends. Missing or redacted native proof is never regenerated from the saved plan. No provider, financial, media, account-wide Memory, job or output records are created.

The exported DDL and service functions have no production importer, schema installer, router, session/cookie ingress, policy provisioner or scheduler. Tests install synthetic terms only in disposable local SQLite databases. No real guest session, sponsor/payer policy, provider request, data-sharing permission, account, OTP delivery or financial hold was changed.

## Expired original-source retirement

`retireExpiredGuestImageSource` is an internal operation for exactly one immutable source session. It uses database time, immutable explicit source/session policy records, native deterministic IDs, original commit/client receipts and exact native event/custody associations. It erases only the due original draft and its bounded original private event copies. Session expiry, policy revocation or a claiming lease cannot extend agreed source retention. Prepared-only sources, a draft already cleared by native cleanup, repeated retirement and a lost acknowledgement are supported. Every return rechecks the actual erased state and unchanged associations, including creation times and preserved preexisting canonical redaction markers. Public event history, original actor, resource/event IDs, source/claim receipts and financial history remain unchanged.

The actual native Memory-origin exclusion protects the draft even when another lifecycle's registration is malformed or its body was retyped. Bounded original-event registration exclusions also refuse contradictory ownership of the source event copies. Exact schema/absence and custody observations remain in the atomic mutation and final proof; this does not perform any Memory lifecycle cleanup. An unrelated or conflicting body/registration is not swept as part of guest expiration.

When the original plan body remains intact, retirement verifies the original private event bytes against it. If the draft was already erased, those original private bytes cannot be re-proven from their hash alone. The operation then relies on immutable original event IDs/receipts, exact native metadata and the due source policy to erase the original associated copies. Metadata-preserving private-text drift is still erased at the original deadline; this branch is not represented as verification that the private bytes remained unchanged.

The 82 focused SQLite checks cover due boundaries, prepared/committed sources, original-copy scope, missing and contradictory native evidence, registration/schema/custody races, concurrent commit, lost acknowledgements, final metadata checks and refusal of resurrection. The original complete empty native-schema case compiled the consequential SQL at expression depth 100. That did not qualify D1 function arguments, bind counts or SQL byte size. Full types and scoped lint pass. Review-discovered final-postcondition and native-provenance failures remain in the evidence alongside their fixes; separate fixture errors are not relabeled as product failures.

Immutable source/commit receipts and native redaction already prevent replacement or resurrection, so no new tombstone, account-wide guest purge or background scheduler is introduced. A future adoption that creates independent target-owned copies must atomically require the source/copies still current, unexpired and unredacted. Any future custody receipt that instead retains guest-owned private envelopes needs a deliberate retention exclusion before that form of adoption is activated. No adoption path exists in this increment.

## D1 compatibility correction

The historical `5023b7a` seal remains 82 passing SQLite/depth checks; publication was held after an independent integration check found a 42-argument `json_object`. D1 documents limits of 32 function arguments, 100 bound parameters and 100,000 SQL bytes. [Cloudflare D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

The successor uses a 26-argument base object and 17-argument `json_set` to produce the same flat witness, including original key order and explicit null fields. It does not remove any provenance, custody or private-copy assertion. A native-parser regression reproduces the original rejection with `SQLITE_LIMIT_FUNCTION_ARG=32`; historical red evidence is retained. The test compiler's optional stricter mode also applies variable-number and SQL-byte limits while preserving its existing depth-only default. It checks raw UTF-8 SQL length independently of the test-only EXPLAIN prefix, actual bound arrays and cache separation between limit settings. Absent and complete native Memory schemas qualify the actual retirement queries, and boundary tests cover 32/33 arguments, 100/101 variable indices and 100,000/100,001 bytes.

These are concrete next implementation steps, not prerequisites for the dormant source increment and not evidence that the deferred all-output generation architecture must be rebuilt.
