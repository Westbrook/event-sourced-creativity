# Dormant native guest Image source

This increment makes one real native Image source from an explicitly authorized guest session. It does not activate anonymous entry, generation or account adoption. The session/claim ledger alone cannot authorize storage: a separately persisted, reviewed source policy must bind the exact immutable session policy/terms, approved Image release, maximum draft/event bytes, maximum event count and draft lifetime. There are no launch values or policy defaults. The seven-day validation maximum is a technical ceiling, not acceptance of a seven-day guest retention policy.

`prepareGuestImageSource` requires both purpose-separated guest proofs and the exact approved origin. It accepts the server-owned session intent, actual registered Image release and native context-block field provenance. Reference assets and other output shapes are refused. The real `validateIntakeRequest` and `buildExperiencePlan` produce the draft, Project, Document, blocks and native client event identities. The reserved Project/Document IDs must already equal the native compiler's identities; historical random-ID sessions fail without migration. A native `experience-draft` private body stores the unchanged plan. Immutable source receipts contain identifiers, digests, counts and expiry, not creative text.

The shared private-content change permits an explicit expiry ceiling for `experience-draft` only when a valid fixed draft identity and current SQL guard are supplied. It caps at the earlier native retention limit and supplied ceiling, validates nonempty well-formed UTF-8 content at no more than 65,536 bytes, and rechecks database identity and the deadline after asynchronous native policy/cleanup reads. Ordinary callers and other kinds keep their existing behavior. The guest source's transaction also asserts the current session/policies, exact body/expiry and original stream/custody. It never extends tighter native retention.

`commitGuestImageSource` commits the unchanged stored native plan once. The existing native event writer produces the actual public event envelopes, erasable private payloads and native client receipts in one atomic batch with a source-commit receipt. The original actor is explicitly the guest subject; no `PilotUser`, trusted identity header or account row is invented. Final reads verify the complete original event set, private and public payloads, exact owner/Project/Document, actor, sequence and native correlation fields. Its `status: complete` means that source commit completed; every result explicitly says `custodyTransferred: false`.

Exact retries preserve original IDs, content and expiry. A changed request cannot replace the source under the same session. Concurrent calls and a lost database acknowledgement recover the actual original receipt. Session/overall policy expiry or revocation removes usable guest authority. Revocation of only new source storage prevents a first commit while allowing current guest reads and completed-source replay until the original lifetime ends. Missing or redacted native proof is never regenerated from the saved plan. No provider, financial, media, account-wide Memory, job or output records are created.

The exported DDL and service functions have no production importer, schema installer, router, session/cookie ingress, policy provisioner or scheduler. Tests install synthetic terms only in disposable local SQLite databases. No real guest session, sponsor/payer policy, provider request, data-sharing permission, account, OTP delivery or financial hold was changed.

## Focused validation and current boundary

Independent review approved the exact source/storage implementation and tests after 42 native-source and 16 bounded-storage SQLite checks passed. Full types, scoped lint and diff checks passed. Tests use the actual native compiler, private storage, event append/private envelopes and context reducer. They exercise duplicate and concurrent prepare/commit, lost acknowledgements, current session/storage authority, body/event limits, preserved expiry, current Project/Document/content custody, exact native evidence, redaction refusal and database substitution at final reads/recovery. No live provider journey was repeated.

Review identified a late Project/Document custody predicate omission. Six pre-fix failing checks were preserved; every saved proof and atomic commit now rechecks those native boundaries. Review also tightened asynchronous database continuity before final disclosure. An initial missing module path, lost-ack fixture intercepting a schema-read batch, and attempted fixture edits blocked by native append-only event triggers were test setup failures; their logs remain separate from this genuine guard repair. The strip-types runner's pre-existing unsupported parameter-property import is retained; transform-types runs the exact current source without build extraction.

This is a fixed-source service, with no general guest native reader/editor or removal ingress. Any later such integration must enforce native DocumentRemoved/ProjectRemoved and complete current custody semantics. Native event private copies have no expiry column; a dedicated source-only expiry eraser and operational retention wiring are required before activation. Those conditions do not authorize a scheduler, claim completion or new public policy.

## Next custody integration

A context-only claim can be qualified independently of generated-result custody. Build a server-minted inventory witness over this exact native source, current private body/event copies and all dependencies; do not treat the claim lease's caller-provided digest as that witness. Existing canonical login can supply the destination through the already implemented native principal checks. A new OTP issuer is not a dependency of that path.

The minimally invasive native path is an adopted baseline in the destination account's native event stream, preserving the original Project, Document and context resource IDs. New adoption/lineage receipts must point to the immutable original guest event IDs and source hashes. Original guest events are not moved, resequenced, reauthored or relabeled, and original execution actor/payer/history is never rewritten. An atomic final operation must validate the still-current claim lease, native destination authority and exact source/copy witness, install the target baseline/custody receipt, complete the claim and revoke guest authority. Existing target event sequences remain intact.

This source-only stage contains no generated result. Generated-result adoption must separately teach the relevant native retained-result readers and future authoring path how to use a truthful custody receipt while retaining original command/completion/provider/financial provenance. It cannot manufacture a target-owned completion event just to pass original-owner checks. Media requires complete dependency manifests, staged verified R2 copies, atomic final receipt and interrupted-copy cleanup. These are concrete next implementation steps, not prerequisites for the dormant source increment and not evidence that the deferred all-output generation architecture must be rebuilt.
