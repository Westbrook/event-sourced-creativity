# Selected sharing of completed original recoveries

This additive increment supports the completed original Video/GLB recovery provenance produced by Forma and a current GLB explicitly restored from its original revision. It leaves the selected-share dispatcher closed and changes no native recovery writer, private retained handler, provider, financial record, schema, retention scheduler, client or file route. No live share or provider journey is part of this verification.

## Current restored GLB and genuine original custody

A current specialized Outputs GLB can acquire the original-to-current relation only when its actual latest private edit is an explicit original restore: `document-artifact-history`, `revision_action: "restore"`, `restored_from_revision: 0`, and `model3d_revision: null`. The current body must contain no audio, video or model3d media-revision record. The existing current native principal, receipt, contiguous edit history, content hash, source and expiry guards remain required.

The adapter reads the genuine retained revision0 snapshot with the existing native source guard. Its actual JSON hash and raw content must equal the current restored content. The existing completed-only original Model3D reader then validates that real original snapshot against the original completion and private input, completed job, plan/grant, paid provider call and acknowledged published storage. It is never called through a recovery lease. The sharing authority separately retains its exact authorization envelope/preflight, actor=payer, sponsor exclusion and current publishing-policy requirements.

The final current-custody SELECT joins the retained original snapshot, complete native original proof and existing current restore/content/event proofs. Original snapshot and input expiry remain effective deadlines. The selected file must match both the native receipt's primary hash/length and `evidence.files[0]` URL/MIME. A different second GLB cannot borrow the first GLB's primary qualification merely because both files have private storage receipts.

The authentic private snapshot records `nativeOriginal`, a frozen relation between original revision0 and the actual selected revision/content/media identities. Its presence is an observation issued by the opaque custody adapter, not publication permission. The restored candidate, public-read lookup and file proof retain the real current revision and hash. They do not relabel a current DTO as revision0 or substitute original bytes under a scaled selection. Original and ordinary custody behavior remains intact; other specialized edited shapes receive no new sharing permission.

The additional original snapshot initially pushed the complete sharing transaction over D1's expression-depth limit. For this restored branch only, the native witness now selects `1` when its unchanged predicate holds; the existing scalar `permitted=1` still denies false, NULL or missing evidence. The final native proof groups the complete unchanged source guard and ordered media predicates without parsing SQL or changing their bindings. Original and ordinary branches keep their previous query text. The failed actual transaction and strict compilation checks are preserved with the final verification.

## Completed recovery metadata

The new pure parser recognizes only the corresponding producer's completed original recovery grammar. The authority's media query can observe the matching recovery completion client in addition to the normal renderer client; the validated branch must match the selected media kind. Text and ordinary Document guards remain unchanged.

Newly published recovery completions require `output-video-recovery` or `output-model3d-recovery`, private root `recovered: true`, and the matching completed recovery checkpoint. A normal renderer completion may instead have the exact completed checkpoint without a recovered marker when recovery finalized an already durable result. A checkpoint or marker alone grants no custody or publishing permission.

The parser validates the checkpoint version/status/completion, original job/slot/client/provider/request identities, producer field grammar and bounded audit fields. A completed historical lease may have expired; it is neither a new active lease nor a current sharing deadline. Original attempt0, no previous replacement slot, personal actor=payer, completed grant and all final native/authority/source proofs remain required.

Allowed recovery keys are confined to the matching result root and the correct private completion root. The parser continues into every allowed subtree and refuses unknown recovery paths or sponsor/workflow/replacement keys. Requests and authorization envelopes gain no exceptions. Captured direct inputs reject accessors, unsupported prototypes, sparse/extra array properties, cycles and size/depth limits before interpretation.

Video retains the existing original/retrieved native recovery evidence validation, including the actual decisive retained provider-envelope bodies. Model3D's historical lease and envelope arrays receive their closed bounded grammar and identity checks. Its historical file arrays receive bounded closed metadata keys and coarse string checks, not full native file semantic validation. None of these audit arrays is represented as independently verified provider-envelope bodies or used instead of the selected file's native paid/storage proof.

## Exact supported scope and limits

This addresses a concrete dependency of the accepted 3D journey: its original was recovered, then scale revision1 was explicitly restored to original bytes as current revision2. The acceptance receipt is reused; no real file bytes or live journey were reread here. Older native file/decode evidence is not silently promoted to acceptance under a newer selected-sharing byte profile.

The accepted Video receipt also records a saved Notes edit with unchanged MP4 but omits its artifact revision. This increment adds recovered original Video provenance; it does not yet add a nonzero current Video Notes bridge. The mapped follow-up uses the genuine original snapshot identified by private `video_content_sha256`, exact current edit/hash, and comparison allowing only the actual single item's Notes difference. Current revision metadata and that bounded branch require their own reviewed work.

Scaled GLB, specialized trimmed Video, replacements, workflows, unknown recovery schemas and transformed projection policies remain outside this increment. The separately sealed GLB projector is optional compatibility work and is not activated here. MP3 and Image work remain separate. The deferred server-owned generation architecture is not a dependency.
