# Dormant guest Image requirement save

This increment saves and reads one unconfirmed native Image requirement from an actual committed guest source. It is internal code with no router, UI, schema installer, live policy, account, provider, or financial activation. Canonical principal and output-command behavior remains unchanged.

## Authority and exact native footprint

`saveGuestImageRequirement(request, env, {proof, campaignId, policyDigest, draftHash})` accepts a closed internal input. The existing two-purpose guest credentials remain separate from the current durable payer approval. The new approved-campaign reader loads the actual immutable v3 approval command, recompiles its reviewed terms, checks the exact original native payer authority snapshot and current eligibility, and returns an opaque request/env/DB-bound witness. It does not authenticate the guest request as the payer or construct a canonical guest account.

The writer derives the native requirement, IDs, SAVE key and envelope from the original guest plan. It preserves the original bare guest event actor, owner, project/Document IDs, source events, source commit head and immutable draft hash. Exactly one native `BlockCreated` and private event body use `server:guest-output`; one `output_commands` row records the original logical SAVE. The new requirement retains interpreted value origins and is unconfirmed. No plan revision, preflight, grant, job, hold, asset, result or media object is produced.

One existing `text-intake` resource receipt accounts for preparation. Its identity is `${saveKey}:text`, its digest covers the exact SAVE envelope, and its text-byte count comes from the actual original context snapshot. The receipt counts finite preparation work; it is not a provider invoice, money reservation or execution permission. A later confirmed-source driver performs distinct work and must account for it separately.

All three writes share one native transaction. Its BEFORE proof includes the unchanged empty-output source inventory, current guest/session/source policy, retained original source, no claim lease, the actual approved campaign/current payer, and closed guest-associated sponsor graph. Its AFTER proof permits only the exact N+1 event/private-body/command/resource successor and repeats current authority. The native event-stage trigger can report multiple changed rows: the writer accepts a positive safe count and proves the exact footprint in SQL. Direct command/resource insertions require one changed row.

An uncertain acknowledgement never causes automatic remutation, a new event ID, a later head or another resource purchase. Only a complete current read of the exact original can resolve it. `readGuestImageRequirement` returns null only for a proven complete empty source; partial or unsupported later states fail closed. Both functions disclose source-free status/identifiers with `planConfirmed`, `admissionCommitted`, `generationAvailable` and `custodyTransferred` all false.

The original private source and policy must remain current after the last asynchronous observation and inside the transaction. Both bearer purposes, origin, captured Request headers, DB binding and cancellation are checked; no secret is persisted in the SAVE envelope or response. The internal API does not consume an HTTP body or deliver cookies. Its future ingress remains a separate reviewed integration.

## Bounded custody and retention consequences

The existing context-only claim inventory correctly rejects an Output tail. Saving a requirement therefore makes that narrow claim path unavailable. A separately qualified context-plus-requirement/result custody successor remains necessary before activating a flow that promises later account claiming. Neither source history nor the original context-only inventory is weakened here.

Completed context adoption and this SAVE cannot both commit. A stale coordinator can, however, inspect the original prefix, pause until SAVE commits, and then acquire a lease: the existing lease primitive does not repeat the inventory/head proof. Adoption fails and subsequent first-SAVE reads fail closed on that lease. This partial-lease race is a concrete concurrency defect in the new composition, to be repaired in the next bounded successor with a genuine inventory/head assertion inside lease acquisition. It is not a successful account claim.

Access expires with the original source. Physical erasure has a distinct limit: the existing expiration helper redacts the original draft and original N event bodies, not the new requirement body. That body contains derived recipe/ratio and provenance rather than the original creative context. Exact tail cleanup remains a bounded follow-up before activating promised guest retention; this increment does not claim it has been implemented.

Memory uses the native helper's independently supported schema-family states and exact observed legacy schema, with malformed or partial native families refused. Unrelated dormant sponsor families can be completely absent; present families require exact schema qualification and complete relevant-row exclusion, including otherwise unexpected explicitly named objects attached to their tables. The exact existing native sponsor actor-history index is a qualified optional definition. Retained driver/issuer identity JSON must be bounded, valid and object-shaped with each required identity selector present exactly once as text; unknown identity is never treated as unrelated. Supported native records of other actors remain permitted. Typed original context block IDs and the new requirement ID must have no foreign project-resource association before or after SAVE. The writer never installs a missing schema or falls back to canonical/unsponsored execution.

Provider/media egress is denied and financial/native histories are checked for unintended changes. The qualification packet records exact source hashes, test counts, query limits and preserved failures; local workerd evidence is not a deployed endpoint, hosted provider journey, browser or physical-device result.

The registered text-only Image source currently produces eight original events, although the source policy permits up to sixteen. Tests must qualify the reachable registered input and its real text bounds rather than fabricate a sixteen-event release. Native trigger acknowledgement, per-family Memory state, exact successor closure and replay must be verified under actual composed queries, including the CHECK wrapper.

Historical regressions for foreign typed block associations, unrecognized sponsor-table triggers, the legitimate optional native index and unclassifiable retained identity JSON are preserved separately from fixture errors and passing engine-compatibility runs. They establish bounded proof-completeness defects, not a demonstrated cross-owner disclosure or an exposed database-administration attack.
