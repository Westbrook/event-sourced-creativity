## Retirement and actual UI fix

The extra consent is immutable and removed on base-boundary change or enrollment
invalidation. Direct opt-in removal dismisses dependent selections, which retires
private consumer copies through the existing graph. Recreating a range does not
reactivate a dismissed context. Changing either owner's project hierarchy retires
a cross-owner context. Source and target Forget keep financial receipts intact.

Browser verification exposed an existing self-abort: the parent privacy barrier
unmounted the recall control during its own consent write. The parent now retires
private presentations synchronously and keeps the remaining controls **hidden and
inert, but connected**, until the write settles. No old private view is revived.
A failed/lost acknowledgement still requires refresh and is never retried.
