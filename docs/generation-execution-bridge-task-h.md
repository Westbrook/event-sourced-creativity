## Durable boundary and trusted host contract

`execution-plan.mjs` snapshots the complete B manifest, C capture projection, F2 result, runtime source hashes, preparation gap and actual JSON bodies before asynchronous admission. Direct requests match the current adapter byte for byte for both C arms. PNG, `n:1`, user safety identifier, high quality and 1536×1024 are explicit. Moderation, stream, partial images, output compression and reference fields remain omitted. Omission is not a claim about provider-effective settings. No extra checker or evaluator is added.

`execution-journal.mjs` uses local SQLite with `BEGIN IMMEDIATE`, `synchronous=FULL`, a unique durable database identity and restricted file permissions. This is a single-host durable implementation, not a deployed D1/distributed lock claim. Reservation and dispatch intent commit before external stage work. Immutable journal events preserve the original operation/provider/request and financial checkpoints before fallible private response writes. No private prompts or raw provider exception messages are written to the accounting journal. Private A bodies remain behind the injected custody boundary, which must independently recheck access and deadline at actual I/O.

The bridge has no default authority, custody or provider transport. Host dependencies are server configuration, never request payloads. Before an enabled stage, the future host must resolve the existing authenticated owner, current source retention, exact reviewed execution/candidate/financial/runtime identities and existing paid grant. The admission receipt must bind the canonical journal identity, exact cell/prompt, stage allowances and expiry. A boolean such as `authorized:true` has no effect. Never substitute B's standalone caller-boolean incident verifier for this authority. Do not expose `mock-host.mjs` to a production entry point.

A future host must attach its existing paid-call reservation/grant workflow to this same canonical ledger/transaction domain, account for outstanding operations outside it, and prove crash consistency before enabling it. There is no claim that two separate databases can atomically reserve together. A new journal path, owner label, manifest ID or trial ID must not escape outstanding exposure. Journal identity binding rejects an alternate empty database under an existing authority. Operation identity also excludes the cosmetic manifest/experiment name; changing it cannot purchase the same pixels again. Actual source, direction, prompt, reference, runtime or model changes need a new reviewed trial, and an unresolved operation still blocks the owner scope.

Each stage is claimed once. Competing connections and a killed process cannot reclaim submitted work. Completed cases verify retained evidence and bytes. Missing/corrupt evidence holds; it does not purchase replacements. Accepted/submitted/uncertain image requests permit at most one status and one result read over their lifetime, with separate current reconciliation authority, against the original provider/request. Failed reads consume their slot. Missing identity or unsupported retrieval holds without a request. Direct Images retrieval is currently unqualified, so its production path holds. Reconciliation retains evidence and cannot itself clear settlement/custody uncertainty or invoke generation.

Explicit stop prevents subsequent stages. Resume can continue a safely paused operation after settled moderation without repeating that check. A lost in-memory image at a storage boundary holds for the original result. Stops do not cancel or refund an in-flight purchase. Missing usage keeps content outcome separate: returned bytes can be retained under the reserved storage stage while accounting remains unknown and new work stops. Measured charges exceeding an allowance remain measured charges; the run holds. Application allowances are not provider-enforced maximum charges.
