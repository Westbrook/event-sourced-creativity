## Tested implementation boundaries

The optional SQL installs no data and has no runtime installer. A server-owned reviewed grant binds the existing authenticated personal owner, exact plan/runtime, retained source/direction references and byte hashes, expiry and authority version. It cannot be created by a request boolean. This first host deliberately accepts only an existing personal administrator through `requireExistingHoldAdministrator`; project/pilot/impersonation/Memory-derived sources need their own qualified binding, not relaxed access. Current principal, retention, native Memory exclusion and exact source content predicates are rechecked within each relevant D1 batch and around object I/O. An identical hash without current custody does not pass.

The host consumes H's sealed B/C request identity and frozen direct request bytes. New request URLs, model aliases, quality, size, fields, references or moderation payload changes fail the fixed contract. There is one moderation POST and, after a valid pass, one image POST. Fetch redirects are rejected; no retry, polling or replacement request exists. Intent commits before fetch; a crash on either side of that boundary holds. Duplicate JSON keys, invalid UTF-8, oversized bodies, invalid moderation cardinality/flags, malformed base64, invalid PNG chunks/CRC/scanlines, unsupported PNG decoding, wrong dimensions/MIME all stop. Supported PNG output is decoded as 8-bit RGB/RGBA at 1536×1024; interlaced/indexed/other-depth PNGs hold as unsupported. A successful decode says nothing about visual fidelity.

Provider request identity and allowlisted usage totals are durably checkpointed before fallible private response/artifact writes. Raw bodies stay private; arbitrary `usage` extensions never enter billing rows. Missing usage, timeout, ambiguous error or storage failure keeps the original hold. Usage arithmetic is an uncached estimate; the host never invents cached tokens or calls it a measured charge. A separate verified original billing record, bound to the exact plan/stage/limit scope, is required to settle the existing account reservations. Incurred charges can settle while residual infrastructure/retention/deletion exposure stays unknown: that operation still holds and blocks the next purchase. Only separately verified zero remaining exposure permits completion; this is reconciliation of this operation, not a provider hard-cap requirement. No charge-ingestion endpoint or residual-risk acceptance path is activated. Reconciliation reuses native idempotent settlement helpers; a crash between token and dollar settlement keeps the operation outstanding and resumes the same pair. Measured overruns are recorded without clamping. Direct Images status/result retrieval is absent. Completed reuse checks the original plan, seven private records and artifact digest; missing or corrupt evidence holds without buying again.

Concurrency is one unresolved operation per authenticated payer across grants/manifests, enforced by a unique index and native reservation triggers. Existing external pending/unknown work prevents the first reservation, including older periods. Stop after settled moderation pauses safely; resume does not repeat moderation. A submitted/uncertain stage never returns to the dispatchable state. Replacing an environment's DB after construction is rejected. The trusted deployment must bind the sole existing production DB; neither a request nor a local journal chooses that binding.
