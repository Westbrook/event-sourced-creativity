# N5 — source-advisory attribution and inspection boundary

N5 reproduces and corrects one reporting defect: Still displayed the aggregate category union beside each highlighted idea, although highlighting only established that an isolated fact result was flagged. A synthetic snapshot flagged for violence and a fact flagged for hate made that fact appear associated with violence. The corrected presenter uses that fact's own recorded categories. A legacy receipt without per-item association says the individual categories were not recorded. A flagged result with an empty category map stays flagged with category unavailable.

This is an application attribution result, not a classifier-quality evaluation. It establishes neither an N4 false positive nor a causal phrase. No moderation input, model, threshold, aggregation/admission policy, request count, retry, acknowledgement, or source intent is changed. Exact-prompt and provider-image handling are unchanged. The source-advisory summary names its place before the planner, final compiler, exact-prompt check and image provider; it does not claim that no previous attempt ever reached those stages.

## Route and wire audit

`worker/document-jobs-api.ts` calls `preflightGeneration` before admission and returns 428 for an unacknowledged review. `worker/generation-readiness.ts` calls `moderateGenerationSnapshot`; `src/still/generation-review.ts` preserves the review issue and acknowledgement key; `src/still/app.ts` displays affected ideas. Both cached full-readiness results and previous-safety reuse retain the original probe and capture identity. Reuse is not a new provider call.

The wire input remains `JSON.stringify(snapshot).slice(0, 28000)` followed by the first 24 nonempty fact projections, each truncated to 6,000 JS UTF-16 code units. Projection order is type, role, intent, effect, handle, then properties.text, instruction, value, label, description, with truthy values joined by ` · `. Empty facts are omitted before the 24-item limit. Metadata-only text and disabled/excluded facts still participate as before. Truncation may split JSON or a surrogate pair; N5 preserves this behavior rather than changing safety coverage. Whole-snapshot content and isolated text can therefore differ materially.

The response must have exactly as many valid results as inputs. Association is positional according to the provider batch contract, not independently echoed block IDs; an otherwise valid reordered response is not locally detectable. Invalid/missing/duplicate-key/oversized results remain unknown and never become a synthetic clear verdict. Any flagged result still triggers review. Overall categories remain the sorted union; overall scores remain per-category maxima. Highlights still come only from flagged isolated facts with a nonempty block ID. Snapshot-only flags do not invent a highlighted idea.

The new optional `sourceVerdicts` summary carries input index, original fact index, block ID, kind, truncation, flag, true categories and scores (null if absent). It adds no raw source to readiness. Raw request/response capture, its observer failure isolation, and its hashes are unchanged. Summaries are not a substitute for verified raw bodies. Scores are provider-reported values, not independently calibrated probabilities.

## Inspection decision: prospective contract only

No pre-admission inspector, route, permission, schema, capture witness or body access is added by N5. `inspection: unavailable-before-admission` remains accurate. The existing admitted-job reader is unchanged.

Current capture stores owner/stream/document/project/revision/full-source hash plus original preflight/request identity and private receipt refs/deadlines. `qualifyAdvisoryCapture` qualifies those server-owned links and bounded private custody. Its own contract explicitly says it is never a source-history proof. It does not independently qualify every current source dependency or source-rights lifecycle. Current preflight cache validity uses a context-mutation high-water mark; that is not a complete authorization witness for an export. The admitted-job reader additionally relies on a terminal personal job, GenerationRequested identity, sponsor/native exclusions and final authorization checks. An unadmitted review has no such job. Reusing that reader with a fabricated job/sequence, reading arbitrary refs, or treating body retention as live authority would widen the contract.

A draft reader based on referenced event hashes was rejected during this audit: referenced events alone do not prove a complete dependency census; a missing source-affecting event, changed scope, rights expiry or native/governed provenance could escape a simplistic witness. No draft reader remains in the local patch. The smallest defensible addition requires a prospective witness attached during the existing authorized preflight, qualified by the authoritative source resolver. This is a separate implementation boundary, not a promise to recover old content.

### Minimum future contract and implementation gates

1. **Selection/authentication.** GET-only, exactly one document ID and existing preflight ID; reject extra/duplicate selectors and caller-supplied content IDs. Use hosted identity and the read-only canonical principal/consent check before initializers or retention scheduling. Require personal Still manual image preflight, original owner/creative stream/project/document/revision/source digest. Exclude Memory (including accepted derived sources), governed/project context, sponsored/billing-delegated, workflow, native Output and durable slots. Do not infer these exclusions merely from absence of one field. Resolve them from the original execution authority plus current scope and custody.
2. **Prospective witness.** The ordinary preflight source resolver must attest a complete bounded census of the selected document/project, facts, constraints, attachments, accepted inputs and source rights, with original event IDs/hashes, scope/owner bindings and lifecycle deadlines. Include a versioned exact input manifest captured during existing construction: snapshot/fact index, source fact index, block ID, truncation and per-input hash. Capture failure remains observational and must not change dispatch, valid verdicts or admission policy. Initial support can be strictly manual text-only, no references/3D/derived/rights-bearing sources, complete snapshot under 28,000 characters, at most 128 dependencies; everything else explicitly unavailable. These are proposed inspection limits, never new moderation limits.
3. **Lifetime/cache.** Authorize only while original and selected preflight rows are live. Adopted cache entries point to their original witness and body pair; they cannot mint a new original or extend authority. Effective deadline is the minimum of original/selected preflight expiry, witness/source-rights lifetimes and both original private-record deadlines. Long body retention, an original hash, or an already rendered summary confers no additional access. Legacy/missing witness means unavailable with metadata only; no reconstruction or backfill.
4. **Bounded exact bodies.** Derive at most two server-owned refs from that exact capture. Reuse `qualifyAdvisoryCapture`, personal guards, native-Memory exclusion and private custody predicates where applicable. Require same evidence ID with one request and one response; original envelope hashes, per-operation request/response hashes, immutable original deadlines and origin/adoption binding must match. Maximum 500,000 bytes per record and bounded reply. Report requested/returned models separately. Preserve exact bytes; validate unique-key JSON/cardinality before associating result i with input i. Invalid results show unknown, never a guessed category. Missing/oversized/incomplete bodies stay unavailable; never fetch a replacement.
5. **Currentness and races.** Requalify source census, ownership, scope, rights, original rows, exact content bytes, native/sponsor exclusions, database identity and principal at the end; check deadlines immediately before response. Unknown source mutations or incomplete qualification deny raw disclosure. Prefer authoritative source-reader qualification over a hand-maintained subset of event types. Do not claim historical authorship from currentness alone.
6. **Side effects/UI.** No provider call, preflight refresh, initializer, retention sweep, acknowledgement, job admission, event/source write, retry or paid recovery. Use private/no-store responses and escaped inert rendering. Link only from the selected review with its original IDs. Distinguish verified bodies from reference-only metadata and stage not reached from missing evidence. Preserve the existing explicit acknowledgement control; inspection is not acknowledgement. A Developer UI return link, if flagged, must use trusted report configuration.

Before enabling any reader, source and rebuilt Worker fixtures must prove every gate: cross-owner/stream/document/project/scope; wrong revision/source; forged original/adopter/body IDs and hashes; missing/expired/redacted/deleted/extended records; cache adoption with expired origin; Memory/governed/sponsor/native source exclusions; source rights expiry/change; principal/database/content/source changes during read; incomplete census/retention and malformed bodies; zero DB writes/background work/provider/job/source actions on success and denial. Current custody regression tests cover existing contracts only and do not certify this unimplemented reader.
