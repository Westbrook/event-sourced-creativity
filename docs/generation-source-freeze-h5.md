## Disabled implementation and qualification

That optional schema remains uninstalled in production; mock installation in disposable SQLite is not live readiness.

The adapter uses the complete durable event fold and current-head/source/private-body assertions from `continueOutputTrustedContext`. It serializes the entire established `context.snapshot`, the native document ID/title and an empty standing-constraints list without truncation or rewriting and binds document/project, revision, source head/digest, block versions, producer, evidence reference, authority version, freeze time, actual stored expiry, exact UTF-8 hash and length. The private read returns raw bytes only for trusted server use, permitting H4's unchanged exact request builder; public results contain metadata/digests only. Eligibility is checked at freeze/read time, never guaranteed for a future operation.

Native `preparePrivateContent` rejects `expiryCeiling` for `document-artifact-input`. H5 does not pass it. The separately qualified adapter reads the native retention result, then inserts source and producer receipt together with expiry no later than native retention, 30 days, or any snapshot fact's source/license/rights deadline. Inactive facts are also bounded because the full snapshot retains them. Original event/private content is never extended or cleaned up. Native prepared statements are not executed; no optional cleanup runs. The read verifies actual stored bytes, timestamps and scope for both rows, then rechecks custody and current source/authority before disclosure. Stored expiry is not merely a claimed field.

The same D1 batch asserts principal, source head, private body and deadline before the two inserts; lost acknowledgements produce no success claim or automatic retry. Revocation, redaction, expiry, changed head or scope fail closed on reuse. Current project execution, Memory-authored material, private-content pointer properties, pinned outputs, extracted external source objects and any global preference history are refused. These require a separately qualified atomic custody binding, not selective omission. Global preferences fall outside the reader’s document-private-body proof, and the ordinary preference reducer truncates text; H5 refuses them rather than silently losing full constraints. This narrow proposal does not claim to support every document the ordinary reader can display.

`resolveFreezeConfiguration` uses server-owned configuration only, matches the ordinary planner's effective model/override and project header, requires account/region/config evidence/credential-binding metadata and expiry, and returns an allowlisted record without reading the API key. With missing metadata it remains unavailable. No selected alias is relabelled as a model snapshot. The user has not accepted a financial policy.
