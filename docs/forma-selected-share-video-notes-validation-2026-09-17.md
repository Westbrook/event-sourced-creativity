# Current original Video with Notes: validation contract

This increment admits a current specialized Outputs Video selection whose content differs from its genuine retained original only at `items[0].notes`. It does not assert that the latest operation or every historical operation edited only Notes. A prior trim, genuine original restore, and later direct Notes edit can qualify when all current original-byte proofs hold. The selected revision remains its actual positive value; returning Notes to their original value does not imply revision zero.

`worker/selected-output-share-video-notes.ts` supplies two pure booleans. `selectedOutputShareVideoNotesContent(originalRaw, currentRaw)` accepts raw strings bounded to 1,000,000 UTF-8 bytes each, at most 100,000 JSON value nodes and depth 64. Both bodies must have one item and an own Notes string of at most 80,000 UTF-8 bytes, matching the actual editor limit. Root audio/video/model3d revision fields are refused even when null. Every other parsed key and value must match, including unknown data and missing-versus-present fields. Member order can differ. The helper does not normalize a Document DTO or establish that an original plan is native; authentic native custody supplies that proof.

Before parsing, lexical validation rejects duplicate decoded object keys at any depth, including escaped spellings of a previous key. It also refuses non-finite numbers, unsafe integers and numeric tokens that differ from `JSON.stringify(Number(token))`. This deliberately rejects unusual equivalent spellings, negative zero and rounding/underflow collisions. It preserves canonical safe numbers emitted by the producer rather than silently losing non-Notes source differences. The initial helper accepted duplicate-title and adjacent unsafe-integer counterexamples; those implementer-owned observations are preserved in `/private/tmp/forma-video-notes-authority-evidence-20260917/duplicate-and-number-red.log` and `video-notes-helper-before-json-token-validation.ts`. `selectedOutputShareVideoNotesEdit(privateRaw, expected)` accepts a bounded raw private receipt with exactly the actual direct-editor producer's ten fields: artifact ID/kind, Document, Project, content reference, revision, changed fields, content hash, editing owner and source surface. It requires video, direct Document editor, exact current positive revision and identities, and the producer's ordered `changed_fields:[content_markdown,items]`. That coarse field list is not proof of a Notes delta. Extra media, restore, sponsor, workflow or other fields refuse through the closed grammar. Expected identity fields are captured from data descriptors without calling getters. These pure checks issue no authority or custody and inspect no provider, storage or history.
