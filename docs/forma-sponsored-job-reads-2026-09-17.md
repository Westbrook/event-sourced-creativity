# Sponsored Image Job status reads

This increment adds native, passive sponsored Image status reads to existing Document Jobs detail and `inspection=1` GET. A status request has a fresh server attempt identity and reserves its configured `image-status` allowance before reading native retained creative evidence. The existing resolver proves original issuance, consumption, native job/slot/grant, current principal, Document/output custody and retention; generation authorization expiry or budget exhaustion does not revoke an owned retained completion.

The status response deliberately contains only certified job ID, Document ID, status, updated time, native kind/surface and a versioned `sponsoredRead` marker. It does not expose provider input or inspection diagnostics. No recovery, reconciliation, settlement, Run or provider dispatch occurs on this branch. Job expiry is checked at initial status selection and in its final atomic proof; this is status-specific and does not narrow the independent retained Image result/media lifetime.

Default mixed job lists omit sponsored rows before retained request/result selection and before ordinary recovery logic. They do not charge campaign allowances. An explicit `GET /api/document-jobs?sponsorJobId=<id>` returns one metered sponsored status in `jobs`; a `document` filter must match that exact original. Detail and `inspection=1` use the same ledger, so switching aliases cannot reset campaign/actor quotas. Duplicate/conflicting selectors refuse. There is no new public UI, launch policy, authorization default, schema installer or provisioning change.

Classification uses a retained native personal authorization marker or immutable sponsor consumption, not payer inequality. Ordinary personal, managed-payer and project/organization jobs retain their normal behavior. Native detail reads repeat the exclusion predicate in the actual full-row SQL, so a negative preliminary classification cannot expose a sponsored job that becomes visible before the retained read. Sponsored rows also cannot become an ordinary GET's recovery blocker.

The already reserved absolute monotonic cutoff survives native custody traversal and response streaming. Request cancellation and delayed body consumption do not renew deadlines or refund the immutable attempt. Control lookup is time-bounded, native reads spend the existing byte budget, and the response consumes only the resolver's remainder. Missing policy/schema refuses the scoped sponsored request while ordinary lists remain available.

## Verification and limits

Focused tests use actual native SQLite admission and completion with the existing in-memory provider fixture; this is not another live-provider acceptance journey. They cover pending/completed detail and inspection, exact selection, mixed ordinary/durable/project behavior, distinct payer without sponsorship, original lineage damage, policy absence/quota sharing, retention and revocation, disclosure races, bytes/deadlines/cancellation, and no provider/R2/financial mutation during status reads. Historical failing runs are retained separately.

This finite slice does not close Outputs snapshots, adopted assets/deliveries, experience-output reads, event/history routes, Job notes or presentation-candidate detail aliases. Those have distinct native contracts and remain explicit follow-up work. In particular, Outputs snapshots traverse whole-Document private source evidence before building their read model; safe metering and mixed-content exclusion require integration before that traversal, not filtering the final DTO.
