# Claimed context: original mini-app settings and reopening

This successor extends the dormant context adoption implemented in `8cead1839f452d11091ed9745c5c53fda57d46f3`. It retains the unchanged original text-only Image plan for the existing canonical destination and supports a separately tagged, read-only mini-app reopening. It does not activate anonymous ingress, provision identity or OTP, install schema, grant provider access, adopt generated media, or complete the full original anonymous mini-app journey.

## Immutable identity and native custody

The original guest plan, hash, stream, event receipts, actor, Project, Document and block IDs remain unchanged. The canonical Document already has its own native baseline under an immutable context-adoption receipt. The new `experience_guest_plan_custodies` mapping associates that receipt with a distinct canonical-owned `experience-draft` private-content ID derived from a purpose-specific domain, session, destination and immutable lineage digest. It never relabels the original global private-content primary key.

First retention is an explicit internal POST operation with current canonical personal Creator authority, consent, current access and the exact completed native context proof. It needs the original guest private plan to remain present, unredacted, unexpired, ordinary personal content and byte/hash identical to its source metadata. It rebuilds the native plan and compares its payloads with the actual adopted private baseline, allowing only the adoption receipt's client key substitution. Original source bodies are never reconstructed from hashes after expiration.

The new canonical copy uses the existing native canonical private-content retention policy. Its separate expiration is recorded immutably; the guest deadline is unchanged. Native storage can clean up already-expired ordinary private rows owned by the canonical destination as part of its existing behavior. The new operation does not alter guest, payer or financial history, and the native Memory exclusion continues to protect registered, marked or retyped evidence.

Private copy, immutable mapping and complete current authority/source/copy postconditions execute in one native database batch. Sibling materialized proof relations preserve complete proofs within D1 expression constraints. Duplicate requests and lost acknowledgments recover the original retained copy. They cannot renew its expiration, recreate a redacted copy or append another Document baseline.

## Read-only reopening

The existing public context-adoption reader retains its original POST/Origin contract. A separate server-internal opaque read witness accepts authenticated GET with its stored origin, refuses foreign Origin and cross-site requests, and remains bound to the exact database and current canonical custody. Its serialized token contains no private bodies or SQL authority; consumers repeat its full proof at the final disclosure or mutation boundary.

`readGuestContextPlan` takes the original draft ID as a selector. It proves the actual canonical owner from the immutable adoption receipt, validates the exact retained copy and current native custody, and returns the unchanged plan plus an explicitly tagged context-only receipt containing the actual canonical baseline events. The guest session need not remain active, and original source expiration/retirement cannot erase the independent canonical copy. Current account revocation, Project/Document removal, custody migration, baseline replacement or private-copy expiration/redaction deny the read.

The existing intake API can serve this tagged result only on explicit original-draft-ID GETs after the ordinary retained reader finds no owner-derived plan. A GET never retains missing bytes, creates schema, commits events or creates an account specifically for a guest. Intent lookup and all non-GET intake behavior remain ordinary. The generic retained reader and generation consumers are unchanged.

The mini-app verifies the tagged receipt in a separate branch, displays the original saved settings and opens the same Document through Edit in Forma. Context-only mode cannot prepare, resubmit or mount the native generation adapter. The original saved settings are not asserted to be the Document's current edited context. Generation remains unavailable; no output binding is invented from transferred settings.

## Remaining original-plan scope

This stage does not prove a public anonymous journey, verified identity activation, sponsor payer policy, generated result/media adoption or generation from the claimed context. The first source remains the bounded text-only Image recipe. Existing signed-in output journeys retain their accepted evidence. No new live provider runs or charges are needed for this implementation's acceptance. Broader server-owned generation remains deferred rather than a prerequisite for reopening saved context.

Qualification and exact source hashes are recorded in the independent evidence handoff; publication and activation are separate decisions owned by the deployment coordinator.

## Qualification boundaries and preserved failures

The focused native tests cover exact private bytes, original expiration and retirement, canonical retention, current consent/role/custody, native Memory provenance, transaction rollback, concurrent copies, replay, lost/malformed acknowledgments and database-binding replacement. Actual local workerd runs cover absent and complete native Memory schemas; queries reached 72 bindings and at most 26,231 UTF-8 SQL bytes. The separate strict-parser helper enforces the published D1 limits of 32 function arguments, 100 parameters and 100,000 SQL bytes, plus the separately measured local workerd expression-depth bound of 100. Pinned workerd itself accepts 33 function arguments, so that engine probe is not misreported as a hosted D1 limit assertion.

Actual API tests exercise explicit plan/receipt GETs, unchanged ordinary canonical intake, current-access denial, no implicit schema/copy creation, and the real server response through `ExperienceIntakeRuntime`. After native Document editing, reopening preserves the original saved settings and the edited same Document. Client and view tests cover malformed custody, readonly recovery, authority-loss/private-state withdrawal, navigation/disposal, and no adapter mounting. Their DOM ports are not evidence of browser layout, physical devices or assistive technology. Current authority is rechecked on reads; this stage does not implement server-pushed revocation monitoring.

Historical new-code failures remain in the evidence: malformed post-commit acknowledgments initially returned an incorrect fresh/replayed classification; four nested async return paths initially missed an outer database-binding replacement. Both have executed red-to-green regressions. A private JSON custody identity identified in review was changed to a digest before final client qualification. Pre-view implementation failures and the prior D1 passing snapshot are retained separately.

An attempted legacy extraction run did not execute product checks: `experience-intake-authority.test.mjs` requires an explicit reviewed manifest, and `experience-intake-boundary.test.mjs` rejects its unprovided `intake-authority.ts` dependency while constructing its harness. These are preserved as configuration/harness evidence, not attributed to this product change. New actual-native API coverage is described above; broader legacy maintenance is coordinated separately.
