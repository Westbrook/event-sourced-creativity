# Exact PNG public derivative preparation

`prepareSelectedOutputSharePngDerivativeV1(input, sourceExpectedFacts, bindings)` prepares one inactive public copy. It snapshots the input before awaiting work, requires the complete sealed historical provenance inspection, removes only the recognized caBX chunk, and independently qualifies the resulting bytes under the unchanged strict PNG v1 gate. It returns a frozen `prepared_derivative` with `activation: "disabled"`, or a refusal. It creates no share, source asset, route, UI, policy activation or provider call.

The original output-only sharing design permits a reviewed, versioned derivative. This helper takes that path without publishing the opaque provider identifier. The private original is unchanged. The copied PNG does **not** retain the embedded C2PA manifest or signature; its receipt states `embedded-C2PA-manifest-removed`. No certificate-trust, privacy-safety, rights or publishing-authority claim is derived from the inspection or hashes.

The only transformation is `source[0:33] + source[13057:source.length]`, after the inspector has proved that these boundaries surround one exact 13,024-byte caBX chunk. Prefix and suffix are copied verbatim and checked byte for byte. PNG signature, IHDR, ordered IDAT stream, IEND and every remaining byte are unchanged. The supported source has no other ancillary chunks. There is no canvas, pixel decoding/re-encoding, compression change, metadata insertion, general cleanup or arbitrary range parameter. Within this inspected format, unchanged image-defining bytes prove unchanged decoded pixel samples.

Unknown fields, rights metadata, unsupported assertions/provenance, additional manifests, malformed chunks or failed local bindings are refused before transformation. An output that would become a valid PNG after blind metadata removal still refuses when its source fails the closed inspector. The derivative receives its own hash, length and strict qualification; a source-file hash or successful source inspection cannot substitute for this check. Its hash equals the verified source `hash.data` digest because both cover exactly the same retained spans, but full source and public-copy hashes remain separate identities.

Expected source facts and bindings use the inspector's closed four-fact and two-binding contracts. They are captured before the first asynchronous boundary. The private receipt binds full source identity, inspector versions/rule digest, current-selection witness, removal range/hash, independent public facts, transform version and publishing scope. It contains no raw request identifier, manifest/instance identifiers, certificate values, disclosure data or original filename. Do not spread that private receipt into recipient DTOs. The nested `public` field contains only exact derivative facts; future routes must still explicitly construct their allowed public payloads.

Only this module's actual in-memory preparation can supply bytes through `copyPreparedSelectedOutputSharePngBytes`. A WeakMap privately retains the strict gate's owned qualification; returned copies are fresh. Forged, serialized or proxied receipts cannot recover bytes, and the preparation itself is not an existing image qualification. Source and temporary public buffers are cleared after preparation. The canonical private original remains under its existing custody; no source-copy API is added.

The eventual native integration must review this exact selected derivative and recheck current source revision, custody, publishing scope and existing authorization before publication. A caller-provided digest alone grants none of those rights. This module does not install that lifecycle or approve an audience. The separate policy question about publishing original opaque provenance is unchanged, but it is not a prerequisite for engineering this copy where that provenance is absent.

Focused verification uses synthetic locally signed fixtures only. It covers exact retained-byte and multi-IDAT/pixel preservation, separate hash linkage, strict requalification, source/copy mutation, forged results, hostile input descriptors, same-size unknown/rights-field refusal, invalid source bindings and metadata, and absence of raw provenance in the receipt. The sealed inspector and DER suites are reused as dependencies rather than rerun as unrelated acceptance work. No actual retained asset or download is transformed in this increment.
