# Dormant guest context custody

This increment qualifies only the existing text-only guest Image context source. It does not activate anonymous ingress, install policy/schema, send an OTP, create an account, generate an output, adopt media, spend money, or grant sharing permission. The eight accepted live output journeys remain separate evidence.

## Authority and custody

The server inventories one already committed guest source. An opaque in-process inventory binds the actual database, original native plan, complete source event/private-envelope/receipt set, current source head, retained draft, guest proof, and closed source-side inventory. A caller-supplied JSON manifest cannot create that authority. The existing claim lease binds that manifest to the actual verified canonical personal Creator and one bounded request identity.

Adoption appends an ordinary native context baseline under the canonical account with the same Project, Document, and block IDs. Target events receive fresh event IDs and purpose-specific client receipts, the native `user` actor, and canonical private-envelope ownership. Original guest events, actor, receipts, draft identities, and financial history are never rewritten. A source-free immutable lineage receipt relates the two exact event sets.

The target baseline, receipts, lineage, and guest revocation use one native `appendEvents` database batch. Assertions bind current source, lease, canonical destination, historical target identity exclusion, and complete public/private target copies. Revocation uses the database clock. No active guest authority survives successful adoption.

## Recovery and removal

A completed adoption is read using current canonical authorization and the immutable lineage receipt. It does not reactivate guest proof or require the original guest private copies to outlive their existing retention deadline. It verifies the target baseline's private hashes and exact current database bytes before disclosure. Native editing appends new events and preserves the same Document; receipt recovery does not rebuild or overwrite those edits.

A removed target Project or Document, redacted baseline private copy, changed custody, or revoked canonical authority denies recovery. An original guest source edited or removed after inventory creation cannot be adopted from that stale inventory. Prior target resource identity, including `DocumentForked`, cannot be overwritten by a new baseline. A later native constructor reusing an adopted resource ID also invalidates receipt recovery; ordinary new context blocks and edits remain supported.

## Limits of this stage

The owner-derived original mini-app draft has not been relabeled. Mini-app draft reopening and generated-output/media custody require their own explicit receipt-aware integration and acceptance. The API therefore reports `contextCustodyTransferred: true` and `miniAppClaimComplete: false`. The dormant source has no generated outputs or media to claim.

This stage uses the existing native authenticated principal as destination. Public guest activation still requires explicit reviewed finite terms and ingress/cookie controls; no new identity provider or OTP mechanism is implied. The broader durable generation redesign is not a prerequisite for this context-only increment.

## Qualification

The final native SQLite suites pass 140/140 cases: 55 inventory and 85 adoption. They cover actual native account authorization, editing/reopening, concurrent custody, loss of acknowledgments, removal, source retirement, and preservation of financial history. Both absent and complete native Memory-schema flows also pass against the pinned local Miniflare/workerd D1 binding, including a forced late transaction rollback and subsequent adoption, recovery, and native editing. Each local-engine flow executes 236 statements after setup; observed maxima are 55 bound parameters and 19,682 SQL UTF-8 bytes. Types and scoped lint pass. Exact source, historical evidence, and independent reviews accompany the handoff; publication is a separate owner-coordinated step.

Historical failures are preserved separately from passing results. They include an inappropriate 8192-character interface-definition limit on an allowed 65536-byte native draft; source issuance-policy revocation changing a retained source manifest; an omitted foreign-stream guest actor; four later native resource-constructor replacement cases; and recovery after 56 actual lease renewals with valid long request IDs. The bounded lease grammar remains unchanged.

The four configured SQLite parser limits (depth 100, function arguments 32, parameters 100, SQL UTF-8 bytes 100000) passed for absent and complete native Memory schemas. Those checks did not model compound SELECT limits. Actual pinned Miniflare/workerd execution exposed the 36-branch compound failure; its isolated probe accepted five terms and rejected six. This is measured local-engine evidence, not a limit stated in Cloudflare's current public D1 table. The successor groups all 36 original exclusions into nine materialized groups of four, at most one matching row per group, with a single outer existence query. No sidecar exclusion is removed.

Local workerd qualification is not a deployed D1 claim, and automated native API/editor qualification is not physical-device evidence. No production activation or publication has been performed by this increment's author.
