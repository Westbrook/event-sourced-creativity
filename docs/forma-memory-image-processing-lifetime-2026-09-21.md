# Memory image processing lifetime and cold-start capacity

## Implemented locally

Private paid-image execution receives one opaque, server-issued **120-second
processing deadline**, before source preparation. It cannot be supplied by HTTP,
serialized, cloned, reissued on the same request, or used with a replaced database.
Both wall and monotonic clocks must remain valid. Ordinary result parsers retain
their 60-second bound and ordinary native reads their existing short deadlines.
Actual source, consent, retention and permission expiries remain upper bounds.

This is a processing window, not permission or a cached access decision. Exact
native source/task/body/head, schema, grant and authority predicates execute
again at transmission, receipt retention, result publication and disclosure.
A managed-pilot exclusion also executes at paid transaction boundaries, including
late enrollment. Verified provider usage settles even when publication is denied.
No uncertain request is repurchased.

The browser receives a separate **at-most-30-second presentation lease**. Serializing
the final response cannot extend it. Ordinary blur/expiry/privacy behavior remains
unchanged; long server processing does not keep private pixels visible longer.

## Native round-trip reduction

- Bootstrap DDL and its dependent column inspection share one checked native
  batch; legacy upgrades and the consent uniqueness index remain intact.
- The canonical result read validates the complete retained task identity in SQL;
  it no longer needs a separate positive task lookup.
- Image source custody predicates replay in the immediately following guarded
  read transaction instead of an additional standalone check. Other authoring
  callers retain the original behavior.
- The same-transaction managed-pilot exclusion replaces a standalone allowance
  lookup. Existing native cost/token reservations retain their own policy checks.

The maximum-three-source shared fixture, with a cold database binding and a
simulated 90-second provider response, uses **50 D1 binding calls**, including
schema initialization. Warm maximum-source execution uses45/47 personal/shared
calls. Maximum-source authored acceptance uses39/45 personal/shared calls;
recovery after Memory withdrawal uses10/9. Both are checked against the same
50-call native request ceiling, with no second provider purchase. A125-second completion is denied and verified usage is settled.
These are local synthetic workerd/D1 observations, **not hosted quota or latency
qualification**. The earlier54-call cold failure is fixed, not waived or excluded.
