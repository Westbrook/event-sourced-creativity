## Delivered contract

`src/model/prompt-provenance-e2a.ts` exposes `projectE2aSource` and `compileE2aPrompt`; compiler version `e2a-approved-proposal-provenance-v1`. The latter calls the existing `prompt-structures.ts` bounded compiler and `prompt-policy.ts` active-fact predicate. Omitting the final treatment argument preserves production compiler output exactly. There is no runtime caller, environment flag, production activation or transport in this module.

The opt-in treatment carries typed `approved-context-proposal-v1` bindings: fact index, block ID and exact complete properties JSON. The trusted source compiler must establish these from the existing producer contract in `context-proposal-application.ts` and the source's provenance; matching field names alone do not establish origin or authorize a private read. V1 removes exactly `context_detail`, `source_execution_id`, `source_proposal_id`, `created_from` at those direct fact-properties locations after shape/identity validation. The private removal ledger retains each original value and source path. No recursive property-name or UUID scrub occurs. Arbitrary nested content and unbound lookalike fields remain unchanged; unknown bookkeeping stays rather than risking semantic deletion.

This deliberately narrow producer profile covers the reviewed leakage. More provenance producers require separate typed bindings, source proof and tests. Bindings fail after properties edits, reordering, inactive facts or contract mismatches. A source change requires a new capture identity and review; it never rewrites a prior capture. Compacted comparisons fail closed because compaction would add another treatment. Direction, all scopes, rationale, repetitions and group semantics stay fixed.
