# Selected-output media interface

This increment builds on the reviewed selected-output media server contract. It supports the existing exact-file WAV, MP4 and GLB profiles. It does not activate creation, install schema, change site access, issue a real token, upload media, call a provider or alter retention. The server creation constant remains false. The initial sharing action stays hidden when creation is unavailable and the current owner has no known links; existing link management remains accessible.

## Selection and review

The native host selects a current retained output and binds a read-only source lease to its Document, artifact, revision, complete retained-content hash, media hash, fixed qualification profile and exact-byte projection policy. Original mini-app MP4 uses the reviewed x264 profile and original mini-app GLB uses the reviewed embedded PNG texture profile. There is no automatic fallback or profile chooser. Document WAV uses its actual current retained media hash and byte length. Mini-app MP3, Image, Storyboard, arbitrary edited GLB and unsupported recovery lineages remain outside this interface increment.

The existing client retains the text serialization and approval contract. The media branch captures the closed candidate fields, verifies source/public media identity equality, reconstructs the native media candidate with the existing projector and checks the complete digest. A candidate supplies no source URL. A host-owned read function binds the current native path and exact media descriptor; replacement of that function or the source lease retires the review.

Review shows the deliberately entered public title, fixed file format, size, duration/dimensions where applicable, required declarations and expiry. It does not display internal hashes, IDs, private titles, prompts or context. The watermark wording describes a source declaration; it does not claim detection or absence. The x264 wording describes the file declaration. Display copy covers English, French, Japanese and Arabic.

No media loads on opening the panel, preparing the candidate or changing language. The user selects Load file. The preview receives one bounded complete owned file only after verifying the expected URL, response, MIME type, byte length and SHA-256. Loading makes the separate Publish action available while that verified file remains held and current. Playback, model viewing and downloading each remain explicit actions; there is no autoplay. A native playback failure clears readiness. A failed 3D view remains unavailable while the already verified file may still be downloaded for review. Publishing consumes the candidate once and retires its preview before awaiting acknowledgement. Existing lost-acknowledgement and explicit-revoke behavior remains unchanged.

## Recipient and file ownership

The intended recipient extension is limited to the server's existing token-bound descriptor and exact `/api/selected-output-shared/:token/file` route. It has no private source port. It must require a complete response with the exact fixed attachment filename, length, MIME type and hash. Recipient wiring was held by automatic review during implementation; its rejected patch and stated reason are retained separately. Until that patch is approved and applied, the existing recipient component remains text-only. No substitute route or indirect implementation is introduced.

The new independent media leaf creates object URLs only for verified owned blobs. Native audio/video controls use `preload="none"`; a 3D view is loaded lazily after View 3D. The separate read-only GLB leaf reuses finite native model validation and view controls without weakening the native viewer URL guard or constructing a private retained DTO. It offers no edit, screenshot, save, generation or context action.

The original parent wall-clock and monotonic expiry remains authoritative through locale changes, file loading and reopening a model view. Source/auth/token replacement, expiry or retirement aborts reads, clears readiness, pauses/resets playback, disposes graphics and revokes owned object URLs. A late response or parse cannot attach to a retired mount. File download uses only the held verified blob and a fixed filename. Removing a displayed file cannot recall bytes already delivered or downloaded; no continuous revocation notification is claimed.

The local transport budget is 256 MiB: a file read reserves three times its declared length for assembly, digest input and Blob, then one copy for the held Blob. Borrowing bytes for GLB retains additional reservations through the actual operation lifetime. Cancellation does not release an unabortable digest/parse reservation early. The budget measures these owned byte representations, not all browser or GPU memory. Native media size limits and the finite GLB validator still apply.

## Qualification and limits

Tests use synthetic JSON, bytes, streams, native frontend ports and closed browser instrumentation. They exercise candidate tampering, exact media identity, source/auth/abort changes, held replies, original expiry, readiness, unsupported profiles and no automatic reads. The publisher component test ports only the imperative leaf to inspect lifetime/readiness wiring; actual file/leaf/model tests qualify that leaf separately. The synthetic browser fixture uses real application components with qualified generated fixtures and no real fetch fallback. Browser observations are not physical-device or assistive-technology evidence.

The local evidence packet records exact source pins, preserved red outcomes, independent reviews and which checks actually ran. Shared server authority and format acceptance are reused from their sealed packets, not rerun as user-provider journeys. A later normal integrated build and root-owned browser readback qualify the combined interface. Whole-original-plan sharing is not complete merely because these finite file profiles are implemented.
