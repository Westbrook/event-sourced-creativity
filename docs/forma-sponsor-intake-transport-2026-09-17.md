# Dormant Image intake transport

This increment composes the existing canonical-principal, text-only Image intake
and separately payer-reviewed intake-read allowance with actual typed HTTP
requests. It is based on reviewed release candidate
`dfdbffd26d808c9d0d866f0d6e89c409ea3a24a0`. The composer is not registered in the
Worker index, host, entry point or client. No schema initializer, campaign,
audience, payer, financial allowance or provider call is activated.

## Request and native custody boundaries

The closed server configuration enables only the Image namespace. An omitted or
explicitly disabled configuration returns without reading the request or
environment. Fresh bootstrap uses the configured campaign. Retained bootstrap,
draft and receipt aliases resolve their original immutable campaign. No client
field selects a payer or waives policy, read allowance or native custody.

Actual POST prepare and commit parse one original bounded body. The opaque
allowance captures its Request, environment, exact database, canonical actor,
action, body digest and deterministic draft identity. The ordinary 32 KiB UTF-8
JSON body limit remains. Sponsored commands also have a five-second server
transport deadline before their policy-backed read lifetime; cancellation does
not await a potentially non-settling stream cancellation. Their reader also
refuses after 1,024 chunks so continuously ready empty chunks cannot starve the
timer. Ordinary callers omit this optional signal/work-bound path.

Every accepted request consumes a fresh database-clock attempt and its complete
byte allocation before protected original or missing-draft probes. The same
allowance covers original, after-save, lost-acknowledgment and native receipt
rereads, including the prepared-result scalar custody check and final response.
Failed work retains its attempt. New requests,
including POST replay and GET aliases, require new attempts. The storage debit
and exact original plan are not recreated on replay.

The original native storage batch and `commitAtomicIntake` transaction remain
the writers. Optional opaque receipt options allow their actual receipt reader
to use the bounded transport. The full native guard and the current complete
read proof remain in the mutation boundary; receipt reads retain exact native
SQL, binding, event grammar and original-row checks. Saved Document staging is
not `OutputPlanConfirmed`, and this composer performs no generation.

## Ordinary aliases

The audit reproduced a concrete protected-read gap in all five ordinary Image
output aliases: their common loader read a marked draft before refusing the
unsupported output path. The intake GET/save/commit aliases also needed a
same-statement negative sponsor boundary, because a preliminary classification
alone could race an atomic sponsored save.

The source-free classifier treats any raw intake linkage or any valid-JSON
`sponsor_intake` property as sponsored evidence, even malformed, null, orphaned,
wrong-actor or expired evidence. It distinguishes exact absent schema from
unavailable or partial schema. Ordinary content reads, final custody checks,
storage and commit guards retain that negative proof in their actual statement,
including the catalog-absence proof. No boolean classification substitutes for
the final native predicate.

Known sponsored ordinary GET aliases use the metered retained-read path. Ordinary
save, commit and output paths refuse known sponsored work before private bytes
cross into application memory. Existing ordinary behavior and the explicit-ID
guest GET context fallback remain; there is no new guest intent or POST fallback.

## Qualification

Preserved initial actual-route evidence records
successful prepare but oversized combined commit receipt SQL. Strict engine
qualification also identified a 104,169-byte native storage statement and a
receipt expression-depth failure. These are new POST composition findings;
the previous four GET read-flow acceptance did not qualify native writes.
Exact duplicate-only composition brought SQL size under the limit, then
exposed expression-depth failures in the prepare CHECK witness and commit root
receipt. Raw parameter transport and two principal-fencing candidates did not
resolve them and were not applied. The statement-level candidate retains every
complete gate and the original failure row. Its 56 exact original/candidate
SQLite comparisons covered each false/NULL gate, consent/role changes, body
mutation and source deletion. All 109 application table states matched, and
previously staged sentinel writes rolled back on every refusal.

The optional native root preparation seam and the existing storage witness now
lift those privately compiled gates to the statement level. Seeded LEFT JOINs
preserve the original CASE failure row; required CROSS JOINs are used only for
reads, where refusal must yield no private rows. The entire original native SQL
and actual binding vector are recognized before transformation. Unknown source
or binding changes refuse. The native root predicate, constraints, default SQL
templates, default binding order and transaction order remain unchanged.

The focused route suite first passed 35 cases. A byte-identical extraction of
the native body reader and sponsor command parser removed an import cycle that
had expanded the native intake fixture's dependency graph to 400 modules.
The final graph is 89 production modules plus its fixture. Eleven affected
route cases passed again on that production freeze; this is a subset rerun, not 46
distinct cases. The six-line extraction-list update passed all four native
fresh-intake tests without changing their assertions or loader guards.

The ordinary alias lane passed 27 cases and the existing guest context lane
passed 23. Fourteen ordinary HTTP/native tests passed on that production freeze,
including fresh commit, exact original recovery, repeat commit, body limits,
registration changes, and historical or concurrently created fork refusal.
Strict SQLite qualification exercised actual POST prepare/commit with expression
depth 100, at most 32 function arguments, 100 parameters and 100,000 SQL bytes.
Observed maxima were 78,898 bytes/77 bindings for prepare and 93,697 bytes/63
bindings for commit. Final emitted statements matched the qualified SQL after
the parser-only extraction.

Independent local workerd/D1 qualification ran two separate empty-custody
fixtures: normal execution and acknowledgments lost after durable writes.
Each performed actual POST prepare/repeat, GET unconfirmed receipt, POST native
commit/completed replay and GET original receipt. Both retained one native
Document, one storage/resource receipt and six complete read allocations;
replay did not replace creative state. Other application and financial tables
remained unchanged, foreign keys were clean, and no external network, media or
provider operation occurred. This executes application functions with a real
local D1 backend, not a deployed Worker or public sponsored service.

Review then found a narrower lifetime gap: the prepared-result scalar custody
query retained its full proof but awaited outside the read deadline. A stalled
query could keep the request pending; the final disclosure guard still refused
unauthorized output. Two regressions against the exact previous module bytes
reproduced the stall. The final opaque helper runs this scalar with the complete
saved proof and read ticket inside the same lifetime. Deadline and cancellation
now refuse promptly, retaining the native original and full attempt charge.
The final five-case affected rerun passed, including loss of the native storage
acknowledgment before the stalled scalar. This adds two distinct regression
cases to the original 35; it does not count repeated checks as new cases.

Strict prepare/commit qualification passed again on the final production freeze;
the new scalar was 85,057 SQL bytes with one packed parameter. Independent local
D1 repeated fresh and exact-replay prepare in normal and durable lost-ACK
scenarios on that freeze. All four POSTs passed with exact native originals and
two full-byte read attempts per scenario. The earlier complete native-commit
D1 evidence remains pinned to the previous freeze; its code was unchanged by
the final scalar fix. All failed and superseded qualification artifacts remain
separate. The lifetime bounds protected reads and disclosure; it does not cancel
or refund a native transaction that has already committed.

Typechecking passed. Scoped lint has one unchanged baseline unused `failure`
import in `project-intake.ts`, reproduced against the original source. The
standard build stopped on the inherited R2 "Selected shared output" component
documentation localization issue before Vite. That predecessor issue is fixed
separately by `0954c1a471b56a556ec1621fdeb34200805013ca` and generated-CEM commit
`e8de908` in the accepted successor baseline. Generated files from this failed
check were restored, and are not part of this increment. The final integrated
release still runs the standard build on that successor baseline.

## Remaining integration

After this increment is qualified, the index/entry/host and opt-in client
transport still need coordinated wiring behind explicit server configuration.
Runtime schema installation and approved launch terms remain disabled. Other
outputs, uploaded/reference input, anonymous onboarding, generated-result
read/download integration and generation UI activation are outside this finite
intake transport increment. Existing retained reads remain independent of new
generation eligibility while their separate read approval and current native
custody must still hold.
