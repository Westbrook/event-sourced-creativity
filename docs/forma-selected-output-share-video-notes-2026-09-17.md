# Current Video Notes and original-byte custody

This bounded successor admits a current specialized Outputs Video whose content differs from its genuine retained original only in the single item's Notes. The actual selected revision may be any positive revision admitted by the existing native history limits. The selected current content hash is tracked separately from the original snapshot hash; they may have the same value when Notes returns to its original content. No first-revision assumption or historical Notes-only claim is made.

The latest private edit must match the closed direct Document editor grammar and current owner, Document, Project, artifact, content, revision and hash. Its public event must match the producer's public projection and exact personal stream, event ID, type, user actor, `web:artifact-editor` client, schema1, and null causation/compensation. These additional columns are checked again in the final custody statement because the generic native event snapshot does not contain them.

The adapter reads the actual retained revision0 snapshot using the existing Video source guard and the original hash in the private completion. It verifies the raw hash, scope, lifetime and bounded content comparison. Every property and array position must agree except `items[0].notes`; root media-revision fields remain unsupported. The comparison accepts unchanged Notes after a later edit, without relabeling the current revision. Unknown normalization, extra content, missing snapshots and unsupported edit shapes fail closed.

The unchanged native original Video reader receives that genuine snapshot's raw content and expiry. It proves the original completion, input, completed job and calls, storage publication and actual MP4. The current one-clip DTO must select its exact URL, MIME, hash and length. Native already-read bytes remain owned through the existing opaque byte capability, with no second R2 read or original-file fallback.

Final custody joins the current raw content and event history, current exact private edit and direct-editor event, genuine original snapshot, and full native original witness. The minimum current/original/native expiry applies. The private `selected-original-with-notes` relation is issued only by that custody proof and carries both content identities plus the exact media identity. The sharing authority separately preserves personal actor=payer, original attempt, authorization/preflight, completed recovery grammar when present, sponsor exclusion and current policy.

An earlier trim followed by genuine original restore and then direct Notes may satisfy this current-only relation. It does not permit exporting the trimmed bytes, prove what the last operation changed, or assert that every earlier operation was Notes-only. Intermediate private snapshots are not an added dependency; the existing native complete public history proof remains required.

Only custody, authority and new bounded helper/test/document files change. Creation remains closed. No existing live output, provider request, invoice, financial hold, schema, retention runtime, client or public sharing action is used. Synthetic native custody, strict byte-profile qualification and actual local D1 composition are recorded separately in the evidence packet. Acceptance of an original native MP4 does not imply acceptance under the stricter public byte profile.
