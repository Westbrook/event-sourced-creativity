# Dormant sponsored Slides contract and native evidence

This additive leaf describes the registered Slides mini-app's existing manual route: **one deck containing exactly five slides**. It supplies review material and current, read-only native evidence. It does not issue or consume sponsorship, admit a job, reserve funds, dispatch a provider request, grant a read, or activate guest access. The shared sponsor policy remains unchanged; policy V5 is reserved for future Slides integration. The leaf template has its own version 1 and family `canonical-five-slide-deck@1`.

## Exact native contract

`experience-sponsor-slides-contract.ts` validates an exact registered release/recipe, `document-slides-manual-v1`, manual production, exact five-slide policy, adapter version, source contract version 2, native execution policy, and the complete frozen composition/repair model routes. Native route provenance, pricing version, effort, default service tier and explicit disabled cache policy are included. It accepts the repository's current Slides models, Terra and Sol, without requiring the two stages to use the same model.

The deck is not five provider calls. It has `planning:0:initial` and one **optional** `planning:0:repair`, with no render call. The ordinary preflight derives each call's maximum input from the source snapshot (`UTF-8 JSON bytes × 4 + 25000`) and uses 6500 maximum output tokens. Each monetary ceiling is the larger of 500000 microusd and the native model-price estimate; the quoted total is the sum of both ceilings. These are application reservations, not provider invoices or a promise that the optional repair runs.

The template bounds a single call to 121500 input tokens plus 6500 output tokens. Both stages share the existing **128000-token reservation**. Their maximum envelopes need not both fit simultaneously: the native runtime checks accumulated usage plus the next request before dispatch and may refuse the optional repair. This leaf refuses a quote whose single-call input ceiling exceeds 121500. It does not weaken or replace the runtime's cumulative token/spend checks.

## Current read-only proof

`experience-sponsor-slides-evidence.ts` accepts only an actor-owned personal Document and its exact native authorize command, current registered release, retained latest confirmed plan and unexpired original quote. It reauthenticates the same actor, recomputes the actual ordinary Slides preflight, checks its whole offered envelope, and reads current source/head/rights/private-body/principal/plan/quote witnesses in one final SQL batch. It captures computation inputs before awaits, preserves original-scope private-body witnesses, rechecks original object/configuration identity and source bytes, and returns frozen evidence. The caller's proposed recipe is captured before the native read begins.

The input lane supports authorized text facts, including the registered claim/evidence message blocks and inferred five-slide format block. Reference, media, audio, sketch and unknown block types or recognized media-bearing properties are unsupported and refused, including inactive and describe-only references. This is a deliberately closed input lane; a describe-only reference is not itself proof that pixels would be transferred. Unsupported material is never silently removed. Natural-language media requests are not comprehensively classified by this predicate.

The reader uses `preparePresentationComparisonRequest`, the actual adapter's offline-only composition seam. It verifies the actual strict `document_slides` schema has exactly five items, `store:false`, the selected initial model/route and 6500 output cap. Returned evidence contains request/schema/JSON-serialized source-contract digests and input/output bounds, with no raw provider body or source prose. Optional undefined source-contract fields are omitted as in native JSON serialization. No repair request digest is invented before a real initial candidate exists.

The composition digest represents offline preparation from the captured authorized context. The paid runtime additionally enriches its compiled snapshot with the Document identity/title and merged standing constraints. Consequently this leaf does **not** claim that its digest is the eventual paid wire, that runtime enrichment already fits a reservation, or that this evidence authorizes that wire. Exact capture and binding at the future execution boundary remain required. The pure template matcher checks shape, hashes and semantic limits; caller-constructed digest-shaped values have no authority without the native reader and later transactional controls.

## Remaining integration

After the shared Short story work is sealed, Slides still needs separately reviewed policy V5, issuer/approval, admission, exact original payer reservation and settlement, native execution dispatch/repair binding, finite read/asset limits, and original-result recovery composition. Recovery must retain the original sponsor payer for reservation lookup while keeping candidate content private to its actor. Mini-app recover-result currently needs explicit Slides integration. No new purchase is recovery, no unused repair is fabricated spend, and immutable sponsor consumption must not be rewritten to resemble an invoice.

The current change creates no route, migration, environment switch, provider callback or new runtime importer. All checks use RAM data and local synthetic native intake/preflight preparation. No accepted live journey is repeated, and no provider, real user asset, private database or financial hold is accessed. Focused qualification and independent-review receipts accompany the implementation; they establish this dormant boundary, not whole sponsored-Slides delivery or subjective deck quality.
