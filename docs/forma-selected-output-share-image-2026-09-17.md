# Exact PNG qualification for selected-output sharing

This source-only prerequisite does not enable sharing. It adds no route, schema, policy, provider call, upload, public audience or changes to ordinary downloads/editing. Current custody and deliberate publishing authority remain separate requirements.

`qualifySelectedOutputShareImage(bytes, expectedFacts)` copies a native, nonshared `Uint8Array` before awaiting work and checks an exact expected SHA-256, byte length, width and height. Expected facts are closed data fields, not getters. The result uses policy `selected-output-share-png-v1`. Qualified source bytes remain private to a WeakMap; `copySelectedOutputShareImageBytes(result)` returns a fresh copy. Serialized or forged facts cannot recover bytes. Retaining the in-memory qualification keeps one bounded byte snapshot alive until garbage collection.

The initial supported subset is noninterlaced, 8-bit RGB/RGBA PNG. It accepts IHDR, contiguous IDAT and final IEND, optional sRGB intent 0–3, standard gAMA 45455, exact standard sRGB cHRM values, and one validated RGB transparent-color tRNS. Optional rendering chunks must precede image data and cannot repeat. This includes the clean original/current-edit synthetic PNG formats already exercised by native Image tests. It does not establish coverage of every provider-produced PNG.

All other chunks refuse, including text, EXIF, ICC profiles, suggested palettes, timestamps, physical-resolution metadata, animation, and unknown extensions. Grayscale, indexed-color, 16-bit, interlaced and non-PNG files also refuse in this increment. This is a conservative supported subset; rejected metadata is not necessarily malicious. No metadata is stripped and no image is transcoded or replaced. A later policy may explicitly qualify additional structures through separate review.

The gate reuses `inspectOutputAsset` for exact digest, format, CRC, zlib/scanline validation, dimensions and expansion limits. Its additional parsing is bounded by the existing 24,000,000-byte native asset limit and 4,096 chunks; native expanded image data is bounded by 32 MiB. Known color fields receive closed value/length checks so they cannot become uninspected string/profile containers. The gate does not claim image-content review, rights, steganography detection, or a guarantee that selected pixels contain no private information.

The focused tests use local authored PNG fixtures only. They preserve the demonstrated boundary that an ordinary private PNG inspector accepts a tEXt chunk while this sharing prerequisite refuses it. Checks cover exact original/edit bytes, RGB transparency and rendering fields, mutation isolation, forged result refusal, hostile input descriptors, hash/dimension/length substitution, disallowed metadata, native malformed-data checks, trailing compressed payload and finite limits.

Next integration must extract/reuse the current native Image custody witness after its active read-hook change freezes, bind the original completed job and current edit to an ordinary-personal publishing witness, and connect this gate to reviewed prepare/commit plus token-scoped media delivery. The text sharing contract is unchanged. Sponsor, guest, shared-project publishing policy and actual audience expansion are not authorized by this helper.
