# Detached selected-media attachment

`selected-output-share-media.ts` is a new pure adapter for an exact locally qualified WAV, Video or GLB. It is not a native custody reader, public share candidate, approval, recipient route or publishing authority. No existing application path calls it. The source dependencies are the separately reviewed Audio gate `16a4ff54fb13c3fe5ec68c49113c21528d9cdac3`, Video chain ending `7886b0529c10926ebfcfe8de4f22463d79c8a8d3`, and GLB gate/texture chain ending `9f23f39650ce0c161f5fc19d2cbe5d2fe7d6c1bd` with the PNG resolution profile `d27f33106ddab7a186b2bf706b59b8480fa9e0bc`. These dependency hashes are not claims that publication occurred.

The declared private selection contains output kind, Document/artifact IDs, current revision, content SHA-256, media SHA-256 and an exact requested qualification policy. Capturing that closed data shape proves no Document exists and grants no access. The adapter never accepts a native DTO, actor, Request, URL, key, source ID or arbitrary descriptor as authority. It snapshots the declaration synchronously, then calls exactly one selected kind's opaque qualification-copy accessor. Only a genuine locally minted gate result supplies bytes. Its policy and digest must match the declaration exactly; there is no fallback from a refused strict profile to another profile.

Supported pairings are PCM WAV v1, strict AVC MP4 v2, the separately selected x264-163-r3060 declaration profile, untextured static GLB v1, and PNG-textured static GLB v1. The latter carries its gate's exact PNG resolution profile transitively; it does not admit arbitrary image metadata. MP3, other formats, unknown profiles, cross-kind and cross-profile substitutions refuse. An explicit encoder profile must retain its existing review/disclosure requirement when integrated; a profile string is not consent.

A successful frozen attachment separates `selection` (private declared identity) from `descriptor` (finite recipient data). The descriptor contains MIME, exact SHA-256 and byte length; Audio adds native sample count/rate/channels/duration, Video adds checked dimensions/duration, and GLB adds no source graph or companion file list. Neither original filename, private path, provider URL, prompts, lyrics, planning prose, receipts, owner details nor the Document/artifact IDs appear in the descriptor. No playable URL is synthesized here.

The attachment's WeakMap privately owns the one copied qualified buffer. Each copy call makes one independent bounded byte copy. Altering returned bytes or the caller's original selection cannot alter subsequent reads; JSON/spread/proxy copies of a qualification or attachment cannot retrieve bytes. Refusing a mismatched selection wipes only the adapter's temporary copy, preserving the original gate's owned bytes. There is no asynchronous work or secondary media fetch inside this adapter.

The later integration must derive and recheck actual current native media custody, original/edited/reset provenance and ordinary personal publication policy; bind the precise selection/profile/descriptor to the reviewed candidate digest and finite expiry; and recheck token, current share row, current principal and custody immediately before recipient delivery. Audio watermark attribution, explicit x264 disclosures and any audience content choices belong in that reviewed integration. Returning a descriptor or buffer here is not permission to send it to anyone. No deferred server-owned generation architecture or automatic retention patch is required to test this dormant data adapter.

The focused tests obtain real opaque results from the existing pure gates, including both Video policies and both GLB policies. Synthetic triangle/PNG/WAV fixtures and the existing test-only two-picture MP4/known encoder fixture are reused; the MP4 fixtures were derived once without running the unrelated accepted gate suite. Tests cover exact byte/descriptor identity, fixed recipient fields, unknown and crossed policy refusal, forged/serialized/proxied objects, accessor avoidance, declared identity separation, independent copies and unchanged gate bytes after refusal. The initial adapter-test setup incorrectly supplied the strict no-SEI fixture to the x264 profile, which correctly refused; the corrected test uses the gate's actual known-declaration fixture. Both outcomes are preserved in the evidence packet. No provider, real retained asset, live share, financial operation or audience change was used.
