# Guest Image stage acceptance repairs

This narrowly scoped successor to `d84849b9d4609f5cfd92cd863d108768ef6456f6` closes three defects reproduced during frozen integration review. The original source, failing cases and logs remain preserved in the independent report's `guest-image-stage-boundary-repair-evidence` packet. No route, provider call, policy, financial hold, schema or paid authorization is changed.

* A real committed preflight reservation returned with one successful acknowledgement slot present only on its array prototype was treated as dense. The request then entered quote construction and wrote one quote. The new stage acknowledgement helper now requires own data properties for every result slot and success flag, and for every required metadata/change count. Inherited properties and accessors cannot supply construction permission. An incomplete acknowledgement retains the original resource receipt and unknown N+2 claim without quote construction or refund.
* After a real lost confirmation acknowledgement, cancellation queued after the complete final lookup/currentness proof but before the confirmation caller continuation still allowed a confirmed receipt to be constructed. The recovery branch now checks the captured request immediately after that await. The original confirmation remains committed; an aborted request receives no receipt and performs no second write.
* A retained quote with a malformed transfer description, coherently rehashed together with its native preflight sidecar, was accepted as the original. The native preflight helper now exposes `outputNativeImageDisclosure()`, a fresh pure description containing its existing Image reason, execution-window values and transfer text. Native Image and Slides returns consume the original fields at their original property positions; Fal and Slides-specific wording/settings stay unchanged. The guest reader compares all three retained fields to the shared pure contract, without reconstructing a quote or reading current provider configuration.

The original increment's type/export-only emitted-code statement applies to its frozen `d84849b` predecessor. This successor additionally extracts the unchanged disclosure literals into the shared pure function. Exact serialized JSON parity against that frozen native builder verifies Image, Slides and Fal offers, including property order; no provider is contacted by these checks.

Verification is limited to the new acknowledgement/cancellation regressions, malformed disclosure variants, native quote shape and serialized parity checks, and one targeted actual local D1 lost-reservation case with a positive construction control. The accepted 55/65 native suites and nine-case D1 suite are preserved as predecessor evidence and are not rerun in full. This successor adds no SQL or schema; it changes acknowledgement/disclosure checks and a final request-currentness check.

The earlier complete-family V1/V2 intake-read qualifier and later private-tail retirement dependencies remain separately coordinated. These repairs do not activate guest generation, supply policy values, implement a Run permission or change the deferred server-owned generation architecture.
