## Paid state and recovery semantics

Each logical call has its own immutable client identity, request digest, phase, model/effort/cap, submitted/received time, provider response/request identifiers, usage/cost evidence and validation outcome. A local validation update is another snapshot of the same call, not another charge.

1. Persist a pending identity before dispatch. A restart may not allocate a new identity for that same paid planning unit.
2. Persist a received private response and its completed call/candidate checkpoint in one database batch before validation or a following repair.
3. Record financial completion independently of private response custody. If source access or retention disappears, financial evidence can finish, but raw/private bytes cannot be restored.
4. Missing/contradictory usage, unknown provider status, or failed durable preservation stops subsequent paid work. Do not replace unknown cost with zero.
5. Exact terminal call evidence can settle the matching original reservations. Failed acknowledgement/repeated reconciliation reuses persisted evidence and repairs only missing audit deltas.

It enforces current actor/project authority, performs no provider fetch, and returns either known reconciliation or a precise `operator_required` result with holds retained. Known accounting does not approve or promote a rejected artifact. Existing recoverable-draft actions stay available when eligibility is still verified.
