# Dormant Audio output continuation contracts

This increment adds explicit read-resource terms, original-payer approval and finite attempt accounting for Audio's native output continuation. It does not connect native preparation, review, admission, Run or a public route. The existing four initial Audio intake operations and V8 generation/financial authority remain separate.

## Closed terms

The policy family is `canonical-audio-output-read@1`, purpose `native-output-continuation`. Every policy explicitly supplies start/expiry, window, actor and campaign request/byte/query/row ceilings, and per-operation byte/query/row/deadline ceilings. There are no default allocations, policy values, payer selections or active campaigns.

| Operation | Intended later native consumer |
| --- | --- |
| `audio-output-state` | Initial preparation state before admitted-job status branches. |
| `audio-output-prepare` | Deliberate original save/confirm/preflight and all own-stage reloads. |
| `audio-output-review` | Passive review of an existing quote, without preparation writes. |
| `audio-output-authorize` | Actual reviewed actor authorization, original replay and fresh post-admission disclosure. |

The terms cover actual repeated reads, control responses, native acknowledgements and final response bytes. Query units count each actual statement; control-row units count returned rows, with a minimum of one for an empty result or mutation acknowledgement. Memoized native data is not a substitute for sponsor read authority. The terms confer no storage, generation, financial reservation, provider, media, polling, recovery or append permission.

The later native context consumer reads the actor's full personal creative stream, including private events from other Documents, before selecting the current Document. That eventual transport must be qualified honestly. This contract slice performs no such creative-source read.

## Genuine approval and private control metadata

A new policy is prepared and approved by the actual original V8 payer through an actual authenticated Request. The approved command binds the exact policy, original campaign and policy digest, original approval, full original payer snapshot, reviewed terms digest and explicit confirmation. Approval records and policies are immutable. A detached DTO, digest, issuer identity, actor consent or boolean cannot approve the policy.

Native authentication includes private project labels in current and historical authorization snapshots. The contract preserves the existing native query and principal/session semantics; it does not replace the principal with a stripped platform snapshot or reject users merely because they have projects. Exact row/type/BLOB-byte bounds apply before authorization metadata leaves SQLite. The actual authenticated payer snapshot must equal the original 13-column snapshot, and the same complete proof must hold in the final approval transaction.

These labels and snapshots remain internal private control metadata. They must not enter client/public policy DTOs, logs or provider requests. Technical bootstrap ceilings bound headers, metadata, queries, returned rows and elapsed time before the payer-owned operation allowance can be selected. Actual bootstrap usage and elapsed lifetime belong to the same eventual ticket. Measuring an already-unbounded result afterward is insufficient.

## Reservation boundary

The attempts module owns its genuine request identity and debit state; it does not import a provisional continuation authority. It authenticates the actual current actor, reads Audio A's exact paired immutable intake provenance and approved terms, and binds the original campaign, draft, Document, session and operation. These original metadata rows establish accounting provenance only, not current native source custody.

A fresh request reserves a fresh immutable operation ceiling. Nested work must retain the same counters and nonrenewing deadline. Failed, denied, cancelled or unknown-acknowledgement work receives no refund; unknown reservation acknowledgement cannot produce a usable ticket. Taking a ticket is one-use, marks consumption before asynchronous proof work, and cannot revive a cloned, mixed, expired or previously consumed handle.

Reservation and taking require the original unconsumed Request. The later controller must perform both before parsing the native command, then meter and capture that command using the same budget. After taking, ordinary consumption of that same body is allowed. This slice does not change the existing handler's parser order. A detected identity change closes the owner permanently; restoring the changed field cannot revive it.

The attempt journal tracks non-provider resource entitlement, never money. Native financial reservation, original payer settlement and purchase idempotency retain their existing owners. Retrying a native operation may require another read debit while recovering the same original command or grant; it must not purchase another result.

The ticket alone exposes no draft/context/quote/native receipt reader, storage capability or provider operation. Future continuation code must prove current native custody itself and adopt the same counters, original deadline and immutable attempt proof. It cannot treat a receipt DTO or successful quota debit as private-read authority. Audio B's initial-intake capability closes with its original request and cannot be reused here.

## Deferred integration

The later read/custody owner, closed native adapter and internal controller remain unimplemented by this slice. Shared propagation must wait for accepted Audio B and Video V7 source freezes. The exact native check-only receipt token will need independently reviewed `intake-authority.ts` and `project-intake-read.ts` seams. A check token presented to `commitAtomicIntake(...,'commit')`, including absent or lost original receipt, must refuse before append; `readOriginal` has no action parameter and cannot itself grant that boundary.

Native source, actor evidence, handoff, Output Requirements, quote evidence and the actual authorizer's post-admission context reload still need finite propagation. The request classifier uses the existing native state, prepare and authorize paths, plus the separately specified dormant passive-review path; it installs none of them. The existing provider/generation architecture, public activation, actual payer terms, schema provisioning, audience, Run, result/media reads and other held patches are outside this contract slice. No broader server-owned generation architecture is made a prerequisite.

## Qualification

Qualification uses synthetic actual native V8 approval, real local SQLite statements, immutable quota/acknowledgement/conflict tests, type checking, scoped lint and independent review. It does not repeat the accepted Audio live journey, call a provider, install real schema, mutate real financial state or establish active sponsorship. Exact test counts and source/evidence pins belong to the supplier packet, not an assumed whole-plan completion claim.

A separately preserved cancellation successor uses the native Request and AbortSignal getters and native EventTarget listeners. A property on the same genuine signal cannot hide actual cancellation. Both standalone approval control and an already-consumed accounting budget stop permanently before later work or disclosure, retaining the original debit. This narrows the unchanged initial-intake transport; it does not change Audio A or renew a deadline. The original 104-test packet and the two reproduced cancellation failures remain historical evidence; the successor has focused qualification on its own exact source pins.
