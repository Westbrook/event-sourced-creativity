    04 · Attributed stakeholder perspectives

    The disagreements made the plan sharper.

    These are actual original, verbatim statements from seven commissioned role-playing stakeholder agents in this study. They are not external customer interviews, employee interviews, or independent market research.

    Lead designer · research agent

    “A smaller screen is not a smaller product; it is a stricter argument about what deserves the next square inch.”

    Decision: Treat the source, authored work, result, and review as one intentional hierarchy. Navigation becomes quiet, stable, and secondary to the creative object.

    Design engineer · research agent

    “The viewport tells the shell how to spend space; the container tells the work surface what it can actually afford.”

    Decision: Define layout from available container size, height, safe area, and input capability—not device names or duplicated application state.

    Product owner · research agent

    “A smaller screen is not permission to ship a smaller product; it is an obligation to present the next meaningful decision first.”

    Decision: Keep five stable semantic destinations and reveal contextual capabilities progressively. Never turn a document view or format into another product.

    Smart phone end user · research agent

    “I am here to finish something, not to reconstruct a desktop sidebar.”

    Decision: Give portrait use a reachable five-destination dock, direct resume and approval actions, privacy-safe async status, and a short-height landscape shell.

    Tablet end user · research agent

    “A pencil should draw, two fingers should move the board, and none of that should depend on owning a keyboard.”

    Decision: Make portrait reading-plus-context and landscape source-plus-making productive. Offer optional orientation guidance without withholding completion.

    Small monitor end user · research agent

    “A half-width window is not a half-capable application.”

    Decision: Preserve two meaningful panes in split-screen; move to a labeled rail and richer context when the application itself—not the physical display—gains room.

    Large monitor end user · research agent

    “I bought screen space to see relationships, decisions, and collaborators together—not to display a larger version of the same cramped interface.”

    Decision: Reveal source, authoring, outcome, and review together when useful; keep an intentional reading width and collapse gracefully when the window narrows.

    05 · Hard passes and delivery gates

    Do not make a polished promise the platform cannot keep.

    These are responsive-strategy risks and launch conditions. Existing authorization, consent, recovery, collaboration, and output boundaries remain authoritative.

    Hard pass · navigation

    Small screens cannot lose a destination.

    Failure: the current 390px shell hides global search; narrow CSS hides the visible Ask/Send action and descendants in actual nested collection trees.

    Gate: the same five creator tasks, visible search, Ask/Send, and complete project hierarchy remain reachable at 320–390px, in landscape, under zoom, and with keyboard-only input.

    Hard pass · attention

    Async status must lead somewhere real.

    Failure: existing project-scoped notifications appear only in one document mode, show at most four entries, and acknowledge a task without opening its exact result or decision.

    Gate: principal-safe Activity aggregates authorized work and directly deep-links each exact resource; optional browser push is not claimed until actually implemented.

    Hard pass · committed state

    A confirmed save cannot ask someone to create it again.

    Failure: an authorized in-app exercise displayed stale-sequence conflict advice after successful commits; retries produced two identically titled research projects and four duplicate role documents. Both projects and all documents were truthfully preserved.

    Gate: client mutation IDs, server-side project/document idempotency, authoritative acknowledgments, visible pending-versus-confirmed states, and reconciliation prove retries cannot duplicate or silently discard a committed project or document.

    Hard pass · truthfulness

    Proposed output is not delivered capability.

    Failure: the interface hides already implemented editable PPTX/DOCX, speaker notes, revision restoration, or independent review—or advertises a generic native report, combined MP4, push, validated visual quality, or live remote cursors before they exist.

    Gate: each existing export, actual revision, real review, evidence state, and collaborator signal maps to its implemented and separately authorized platform contract.

    Release gate · access

    Responsive layout never becomes authorization.

    Failure: hidden panes still fetch protected customer work, another actor’s private conversation or job, inaccessible Canvas data, or privileged internal surfaces.

    Gate: project scope, actor privacy, Canvas entitlement, exact-resource sharing, and revocation remain enforced before data or application bytes load.

    Release gate · interaction

    Touch discovery cannot require touch.

    Failure: pinch, drag, swipe, hover, orientation, or finely positioned gestures become the only way to review, compare, rearrange, approve, or finish.

    Gate: Forma’s own 44px effective-target contract, named buttons, real two-touch Canvas behavior, keyboard/list equivalents, focus return, reduced motion, RTL, and 400% reflow all remain complete.

    Release gate · consent

    Adaptation cannot approve or spend.

    Failure: a suggested action auto-submits paid work, cross-project references, public sharing, or a retried provider operation while a pane appears or changes size.

    Gate: explicit human commitment, exact scope and cost, actor/project reservations, safe recovery, and existing approval ownership remain intact.

    06 · Proposed 12–16 week delivery sequence

    Earn coherence before adding surface area.

    Eight overlapping workstreams produce a useful first release in approximately 4–6 weeks and a comprehensive program in approximately 12–16 weeks. Duration, owners, and outcome targets are proposals—not current delivery claims.

    Weeks 01–02 · Phase 0

    Truth, instrumentation, baseline

    Owners: product owner, lead designer, design engineer, QA/accessibility, privacy.

    • Inventory exact pages, permissions, actor-private jobs, approvals, Canvas, real outputs, committed-state acknowledgments, and responsive failure evidence.
    • Build behavioral tests for hidden phone search, nested folders, actual targets, chat height, landscape, presence, false stale-conflict messaging, and duplicate project/document creation.

    Gate: the observed responsive failures, false successful-save conflicts, and duplicate-create retries reproduce in real interaction tests with no sensitive telemetry.

    Weeks 02–04 · Phase 1

    Adaptive shell and immediate blockers

    Owners: lead designer, design engineers, collaboration/backend, QA/accessibility.

    • Deliver five stable destinations, visible search and Ask/Send, full-depth project navigation, 44px targets, short-height layout, and truthful pending/confirmed save states.
    • Introduce client mutation IDs, server-side idempotency, authoritative acknowledgment/reconciliation, and duplicate-safe create/save retries while preserving drafts and focus.

    Gate: 320px portrait and short-height landscape complete search, navigation, authoring, and authorized Canvas entry; retries never duplicate a committed project or document.

    Weeks 03–06 · Phase 2

    Secure Activity, review, and Deliver

    Owners: product owner, collaboration/backend, privacy/security, design engineering.

    • Extend real recipient-scoped notifications into a principal-safe inbox with exact resource deep links and private/shared separation.
    • Project actual PPTX, DOCX, PDF, revision, approval, output, and review capabilities truthfully across the project.

    Gate: an authorized reviewer reaches the exact current artifact in two interactions without private-job leakage or self-approval.

    Weeks 04–08 · Phase 3

    Phone-first Work, Chat, and slides

    Owners: lead designer, design engineers, document/output owners.

    • Deliver task-first document templates, visible Send, Write/Shape/Present families, conversation-first Chat, and readable phone presentations.
    • Keep current action and composer available above software keyboards in portrait and constrained-height landscape.

    Gate: all seven existing document lenses and supported artifact-review tasks remain completable without forced orientation or draft loss.

    Weeks 05–09 · Phase 4

    Projects, Explore, and continuity

    Owners: product owner, design engineers, research/QA.

    • Make project home, full-depth collections, project Library, Scout, Taste & time, previews, and exact-resource continuation discoverable.
    • Preserve selected object, project authority, chosen pane, scroll, and unsaved work as available space changes.

    Gate: every authorized advanced feature, collection, Library family, and existing lens is reachable in two deliberate contextual actions.

    Weeks 06–11 · Phase 5

    Tablet-native Canvas and direct manipulation

    Owners: Canvas engineer, lead designer, design engineer, QA/accessibility.

    • Implement actual two-pointer pan/pinch, additive touch selection, 44px effective handles, safe pen enhancement, and anchored comments.
    • Preserve accessible list/button equivalents, board identity, project scope, and rotation/split-view continuity.

    Gate: portrait and landscape users select, group, move, inspect, annotate, and review without Shift, hover, leaks, or duplicate writes.

    Weeks 08–13 · Phase 6

    Wide workbench and truthful collaboration

    Owners: design engineer, collaboration/backend, product owner.

    • Compose two to four user-controlled source/work/result/review panes with revision comparison and principal-safe activity.
    • Expose genuine remote presence only after authenticated cross-account transport, exact project access, and consent exist.

    Gate: 2560 → 1440 → 900 → 2560 preserves identity, draft, selection, focus, review revision, and pane intent; no fake cursors.

    Weeks 11–16 · Phase 7

    Specialist parity, trust, and staged rollout

    Owners: product and quality, QA/accessibility, privacy/security, operations, procurement.

    • Verify specialist boundaries, real browsers/devices/assistive technology, performance, RTL, privacy-safe reporting, and reversible pilot rollout.
    • Keep enterprise identity, deletion, recovery, governance, and independent accessibility evidence as separately controlled release gates.

    Gate: no P0/P1 blockers; role, permission, locale, and input matrices pass; unrestricted enterprise remains blocked until its distinct trust evidence exists.

    07 · Implementation signals and evidence

    Adapt the presentation, never duplicate the truth.

    The current application already includes container-query, dynamic-viewport, route, account-popover, project-boundary, and accessibility foundations. The following contracts direct proposed expansion.

    Measure the space Forma actually has.

    Prefer @container for panes and application width; supplement with short-height queries, 100dvh, and safe-area insets. A large display running a narrow window is still a narrow workspace.

    Model input capability, not device identity.

    Use coarse/fine pointer, hover availability, keyboard focus, and explicit user actions. Tablets may have keyboards; laptops may support touch. Orientation is advisory, never a capability gate.

    Preserve one route and one authoring truth.

    Recompose shared panes around the same project ID, document ID, owner, actor, permission epoch, locale, and draft. Bind each create/save to a client mutation ID and authoritative idempotent acknowledgment; never turn a committed result into duplicate-producing retry advice.

    Activity is a scoped workflow, not a badge.

    Separate observable completion from proposed notifications. Filter by exact actor/project permissions; state whether a result is ready, a human decision is required, or a failed operation can safely resume.

    Keep navigation semantics stable.

    Real destination changes remain links; actions remain buttons. Canvas remains an independently entitled project-level surface; Chat remains a view of the same document; guest Review never inherits the signed-in shell.

    Performance and inclusion are release criteria.

    Preserve bounded route modules, containable pane widths, local-only scroll where justified, 44px controls, visible focus, screen-reader names, RTL, 400% reflow, reduced motion, and honest evidence labeling.
