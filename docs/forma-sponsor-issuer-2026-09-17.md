# Disabled canonical-principal Image issuer and internal driver

This increment completes one internal, synthetic-qualified composition of actual native text-only OpenAI Image preflight, approved sponsor issuance, admission, Run, fresh persisted execution authority, provider execution and settlement. It remains inaccessible through registered HTTP routes and queue drivers. No sponsor schema initializer, environment switch, real campaign, audience, payer commitment or financial allowance is activated. Existing personal and shared/project defaults remain unchanged.

## Authority and policy

A version 2 campaign contains one stable, closed Image template. It binds the registered app release, original text-only input, size and output count, ordered planner/render stages and limits, native settings, adapter identity, exact API request contract, moderation contract and full creative-direction JSON schema digest. Those transport values come from constants shared with the actual OpenAI request builders. Version 1 exact-intent policy equality is preserved. Each issued version 2 envelope separately binds its actual immutable preflight route/settings, source, rights, transfer, actor and intent.

An authenticated canonical payer must send the typed approval POST containing the full proposed terms, explicit confirmation and reviewed terms digest. The server validates the digest and saves the immutable full terms, final policy, authenticated payer identity and permission snapshot, actual approval command and database time. A digest or administrator role cannot stand in for the payer's approval. Named issuers are explicitly eligible actors allowed to request their own original Image; general administrative delegation is not implemented. A payer-approved campaign has one immutable policy in this increment. Editing, renewing, replacing or reviving it is refused rather than resetting its aggregate history.

Issuance uses a non-serializable capability bound to the original request, canonical actor, native personal Document custody and exact source. It checks the requested plan revision and single selected Image target against retained native plan/preflight bytes. Current scope, owner stream head, source/rights deadlines, approval and private evidence are checked in the same transaction that inserts the exact grant, resource receipt and immutable issuance record. Replay returns only that original envelope and repeats live authority. Changed content under the same intent conflicts.

Approval and resource liveness reach actual native admission and every paid stage. Revocation disables the approval, campaign, resource policy and outstanding grants without deleting cumulative receipts or refunding consumed entitlement. The execution envelope and synchronous dispatch checks use the earliest policy, resource, issued-grant and native deadlines. Original known monetary settlement deliberately remains independent of live approval, source and campaign liveness; costs belong to the original matched sponsor reservations, while the actor retains creative custody.

## Resource boundary and continuous driver

The internal driver begins with an already saved and confirmed native Document. Its text preparation ticket measures the exact authorized source snapshot; this is not initial Document ingestion, upload or storage-route protection. The driver then acquires a durable preflight ticket before doing native preflight work. Issuance commits its own resource debit with the grant. Limits are explicit reviewed terms, use database time, and aggregate by campaign and canonical actor across intents and sessions. They cover operation counts and source bytes, rolling windows, pending grants and inflight jobs. Inflight capacity is checked again after the active job is inserted in the actual admission transaction.

The driver request body is stream-limited to 4 KiB before parsing; approval commands are limited to 128 KiB. An oversized body with an unfinished tail is refused without waiting for the unused cloned stream branch to close. Resource tickets survive failed work. A ticket with no durable native preflight outcome is an unknown stage and cannot authorize unlimited retries. An exact intent whose preflight ticket was never acquired may atomically acquire it; only the winner performs the work. Durable original native receipts resolve lost acknowledgments without a second purchase.

The continuous internal driver composes the real native command functions and reconstructs fresh execution authority from the admitted immutable grant and exact reservations. Public sponsored Run, resume and direct job execution remain refused, including already queued jobs. Final responses repeat current approval, source custody and exact intent proof with the original job metadata read. This is an internal composition proof, not a public sponsor beta or provider acceptance journey.

## Remaining original-scope work

- Applicable payer/user approval must choose the real payer, exact allowances, eligible audience and supported launch operations. The deployment owner may review and activate only that approved policy; deployment ownership does not authorize selecting financial commitments.
- Public activation still requires an explicitly reviewed schema installation, authenticated approval/issuer entry and internal driver wiring, plus route-specific admission and abuse controls. None is registered by this increment.
- Initial native intake/storage, attachments, uploads, polling and downloads are not sponsor-resource integrated here. Unsupported internal resource operations are refused. Each route needs its own bounded native custody and resource integration before inclusion in a launch.
- The other seven output types, reference-image modes and Fal Image are outside this qualified issuer/driver. Their exact native input, route, rights and execution mappings require separate implementation and qualification. The independent 3D admission work is not part of this patch.
- Anonymous guest identity/onboarding is unfinished. The original plan permits this canonical-principal early-auth beta, but it does not prove anonymous guest completion.
- Reusable campaign editing/renewal and broad delegated administration are unsupported. Any future lifecycle must preserve campaign-wide aggregate history and all original incurred-cost authority.
- Interrupted protected preflight work with an acquired ticket but no durable receipt is explicitly refused as unknown. This increment adds no automatic scheduler or broader server-owned generation architecture.

All tests use disposable local SQLite and intercepted provider transport. No real provider calls, invoices, financial holds, sponsor policy or user permissions are changed. App-recorded usage and synthetic receipt values are not provider invoices. Historical failing qualification logs remain part of the validation packet; the final receipt identifies the exact corrected cases and source hashes.
