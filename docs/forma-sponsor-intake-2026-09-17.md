# Disabled sponsored Image initial intake

This increment connects an explicitly approved intake allowance to actual native text-only Image draft storage and canonical Document creation. It begins without a preexisting Document. It does not activate a public sponsor route, schema migration, environment switch, real campaign, payer commitment or allowance. Anonymous input, uploads and reference images remain unsupported.

## Closed authority and native persistence

Existing ordinary intake already streams at most 32 KiB and permits fewer than 50 prior draft writes per actor in a day. The ordinary predicate is reused without changing its limit or accounting. The new internal typed POST authenticates the canonical personal author, reads the actual payer-approved campaign and validates the registered Image values. It builds the real native plan and preserves its event grammar, IDs and decisions. A server-derived opaque `sponsor_intake` marker is included in the final plan hash; a marker alone never supplies authority.

Resource contract version 2 explicitly lists `image-text-draft-storage` alongside the three previously qualified operations. Version 1 retains its exact fields and meanings and refuses initial storage. Old approvals and already-installed schemas are not silently upgraded. A future schema change requires an explicit reviewed migration; this patch only exports dormant schema definitions for isolated qualification.

The actual `storePrivateContent` transaction inserts the native private draft, cumulative resource debit and immutable sponsorship linkage together. CHECK-backed SQL witnesses join the exact inserted private bytes, native IDs/hash, original retention expiry, actor, approved campaign/policy/resource identities and debit before commit. A post-commit row-count check is not the rollback boundary. Prevalidation rejection produces no receipt. Storage and debit commit together or both roll back; a lost acknowledgment returns the exact original without refreshing its expiry or spending another allowance. An ordinary existing draft cannot later acquire a sponsorship receipt, and the actor's same native intent cannot move between campaigns.

`content_bytes` measures UTF-8 bytes of the serialized retained draft plan, including its release, typed values and events. It is not physical database storage, and it does not separately total the later event/private-envelope representation. The existing validated native grammar, request limits and event-set checks continue to bound that representation; this increment does not widen them.

The first continuous native check exposed an omitted format category in the earlier dormant Image mapper: actual mini-app intake emits authored ratio and default deliverable format blocks. The narrow compatibility predicate now accepts those two registered Image metadata/shape contracts, including native ratio geometry, and rejects unrelated format, extra provider/model/size fields and changed release/binding. Matching metadata is not an attestation that a particular UI originally authored the block. Exact retained preflight and payer-approved templates still own output size, route, calls and spending; a different actual ratio cannot override the approved template. Reference input remains refused. The 3D dispatcher and replay logic are unchanged.

## Explicit review, recovery and boundary

The internal commit requires the exact reviewed draft hash. It passes the saved sponsorship/resource linkage and current new-work authority into the existing all-or-none canonical intake transaction. The same native event and receipt grammar creates the Project, Document and context blocks. This does not imply `OutputPlanConfirmed`: output confirmation remains a separate actual native action.

Exact saved-draft replay runs before fresh daily quota and campaign checks. Completed native Document receipts are recovered under current actor custody and the original immutable linkage, independently of sponsor exhaustion or revocation. New protected commits still require live approval, exact resource policy, eligible actor and database-clock validity. Erased or expired private drafts cannot be recreated through replay. Known financial accounting remains in the previously qualified generation path and is not changed here.

The ordinary native commit endpoint refuses the presence of a `sponsor_intake` marker, including a malformed marker, without querying sponsor tables. This prevents bypassing the internal commit authority. Existing ordinary plans, owner reads and receipt reads keep their native behavior. No public endpoint invokes the new composer.

The current browser intake runtime reconstructs an unmarked plan and would reject this new marked plan. That is an explicit public UI integration gap, not browser qualification. A future reviewed activation must teach the authenticated client to validate the versioned marked contract and original receipt, wire only the approved sponsor operations, and retain ordinary and same-Document behavior. This patch does not relax that client validator.

Remaining work includes actual payer/audience/allowance and launch-operation approval; explicit schema and public wiring; bounded sponsored status/download access; other output/input/provider mappings; and anonymous onboarding only if that policy is selected. Broader administrative delegation or editable campaign lifecycles are not prerequisites of the original first canonical-principal beta. Initial storage closes one original two-stage consumption gap and does not by itself establish a complete public beta or whole-eight-output sponsor rollout.

Qualification uses disposable SQLite and intercepted transport only. No real provider charge, invoice, financial hold, permissions or live policy changes are made. Historical failed results are retained in the validation packet with source-defect versus fixture-maintenance classifications.
