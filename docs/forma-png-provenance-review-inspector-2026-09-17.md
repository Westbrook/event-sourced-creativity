# Disabled PNG provenance review inspection

`inspectSelectedOutputSharePngProvenance(bytes, expectedFacts, bindings)` returns a frozen `review_candidate` with `activation: "disabled"`, or a refusal. It does not return an image qualification, retain a copy capability, publish an asset or enable a policy. The original PNG gates are unchanged and continue refusing `caBX`. Expected facts are the four native PNG facts (SHA-256, byte length, width, height); bindings are exactly `selectionWitnessDigest` and `publishingScopeDigest`. Callers must obtain those bindings from the appropriate authenticated lifecycle. A diagnostic or caller-supplied digest is not authority.

The input and closed data fields are captured before the first await. Shared buffers, proxies/subclasses masquerading as bytes, detached bytes, accessors and unexpected fields refuse. The snapshot is cleared after inspection; only immutable facts and disclosure data are returned. The caller must protect the returned raw metadata values in an authenticated review context. The helper never logs them or sends them to a network endpoint. There is no source-byte or public-byte export API.

The initial profile is the observed noninterlaced RGB8/RGBA8 PNG structure: IHDR, one 13,012-byte caBX at offset 33, IDAT and final IEND. It has one creation-only manifest, exactly `c2pa.actions.v2`, `ai.fal.info` and `c2pa.hash.data`, one claim-v2 and one COSE signature. Known UUIDs, labels, flags, box order, map key order and shortest definite CBOR forms are closed. Bounds remain 24,000,000 PNG bytes, 4,096 PNG chunks, 64 JUMBF boxes/depth 8 and 1,024 CBOR nodes/depth 16. Other PNG metadata, manifest structures, assertions, fields, remote references or unexplained bytes refuse. This intentionally narrower wire subset does not accept every otherwise valid C2PA representation.

Manifest and instance identifiers are lowercase UUIDv4 with RFC 4122 variant bits; the recorded timestamp is calendar-valid UTC with six fractional digits. The generator version has decimal component lengths 1, 2, 1. The request identifier is exactly 91 ASCII bytes matching `[a-z][0-9]-[A-Za-z0-9_-]{86}==`. These are bounded observed grammars, not a decoding or safety claim. Its meaning, linkability and privacy properties remain unestablished. The disclosure includes its exact value, a concise uncertainty statement and the fact that recipients can extract retained metadata.

All references resolve to the three exact local assertion paths or the one signature path in the same manifest. Every assertion digest covers the original assertion JUMBF body, including its descriptor and salt but excluding only the outer eight-byte header. The image binding excludes exactly the complete caBX chunk at offset 33, length 13,024. The detached ES256 signature is verified against the first embedded certificate over `CBOR(["Signature1", protectedHeaderBytes, emptyBytes, originalClaimCborBytes])`. Original signed bytes are never normalized or reserialized for verification. Native PNG inspection still supplies complete file hash, dimensions, CRC, inflate/filter and final-boundary checks.

The separate DER helper accounts for all certificate bytes, including extension payloads and signature scalars. It admits only the observed P-256/ECDSA-SHA-256 field grammar, exact name attributes and known extensions; it checks the subject/issuer and SKI/AKI links plus leaf/root signatures locally. Its organization literal exactly matches the spelling in Fal's [public privacy policy](https://fal.ai/legal/privacy-policy): `fal - Features & Labels Inc.`. The root common name adds the fixed ` Root CA` role; the leaf common name is `fal.ai`. This name match establishes a finite text rule, not issuer authenticity. Unknown names, OIDs, URLs, extensions, extra bytes and alternative encodings refuse. UTF-8 BOMs are preserved as content and rejected, never stripped into accepted names or metadata fields. Current-time validity, revocation, trust anchors and PKI trust are not evaluated.

Each retained metadata byte belongs to exactly one leaf field with a role, source range, encoded digest and display group. The structured certificate disclosure includes names, serials, recorded validity times, algorithm details, every extension OID/value and cryptographic material summaries. The fixed-order review tuples bind source facts, field coverage, policy/parser versions, exact disclosure copy/values and publishing scope. This encoding is only for review identity; it does not replace the original CBOR encoding in a signature or hash. Rule declarations, code and profile/parser versions must be reviewed together when changing the supported subset.

The output says **bounded historical profile/local consistency**, not complete C2PA conformance. In particular, the observed whole-caBX exclusion matches the [official PNG implementation](https://raw.githubusercontent.com/contentauth/c2pa-rs/main/sdk/src/asset_handlers/png_io.rs), while C2PA specification text restricts exclusions overlapping logical-unit headers; current mandatory-actions placement also differs from this gathered-actions layout. This implementation preserves the original declared structure and checks its mathematics. It does not resolve the specification/implementation tension by changing signed metadata or by declaring a trust result. Relevant definitions are [C2PA 2.4](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html), [RFC 9052 §4.4](https://www.rfc-editor.org/rfc/rfc9052.html#section-4.4), [RFC 9053 §2.1](https://www.rfc-editor.org/rfc/rfc9053.html#section-2.1) and [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280.html).

The focused suites construct synthetic locally signed certificates, claims and PNGs. They check full coverage and deterministic disclosure, exact graph/hash/signature binding, hidden fields, altered encodings, mutation and forged-object refusal, finite parsing and native PNG validation. Existing accepted journey suites are not repeated. The five previously downloaded PNG streams also produced disabled candidates in a separate read-only compatibility receipt; their source hashes stayed unchanged. That diagnostic used explicit nonauthoritative placeholder bindings and logged no raw identifiers or disclosure values.

Publishing these original bytes with the opaque identifier requires a separately approved product disclosure path and a concrete per-selection action. The original output-only plan also allows a reviewed, versioned public derivative. Such a separate helper could remove only a completely recognized caBX from an owned copy, preserve the private original and every remaining image byte, and requalify the actual derivative under the unchanged strict PNG gate. This inspector implements neither that transformation nor any publishing route. Metadata removal would not preserve the embedded C2PA manifest/signature in the public derivative, and must not be described otherwise.
