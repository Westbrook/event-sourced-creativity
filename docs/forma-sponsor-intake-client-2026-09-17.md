# Disabled sponsored Image intake client

This increment lets an explicitly selected authenticated Image campaign use the existing intake runtime with the original marked server plan. It adds no entry-point registration, host/store wiring, public endpoint, schema installation, live campaign or generation interface. The new factory requires an injected typed transport; it has no network or endpoint fallback.

The client captures the expected canonical actor and campaign for response consistency. These values supply no server authority. Actual preparation and commit remain the existing server operations that authenticate the actor and enforce the approved campaign, resource allowance and native custody. Read operations continue to use native authenticated draft and original receipt custody; this adapter does not claim a sponsored status/download resource gate.

Opt-in validation preserves the exact `sponsor_intake` marker and full marked plan hash. It checks the marker's closed version and deterministic campaign/actor/intent receipt identity against the native reconstructed request, release, IDs, stream and event set. It returns the original plan without removing the marker or converting it into an ordinary plan. The existing runtime's exact native receipt validation remains in place; responses and appended events are not rewritten.

Ordinary runtime construction still refuses marked plans. The opt-in is text-only Image and cannot accept a reference input or a different output. The expected actor, campaign and transport are captured before asynchronous work. The original prepare/review/submit/recover states, request cancellation and single-flight behavior remain the native runtime's responsibility.

New preparation must match the selected release. A retained older compiled release may be read to recover its original receipt, as in ordinary intake; it does not permit a fresh commit under a changed release. Sponsor revocation and new-work exhaustion do not erase an already completed actor-owned native receipt. A missing, erased or expired draft still cannot be recreated by client recovery.

Qualification composes the client with actual server preparation, native storage and commit, and native authenticated reads in disposable SQLite. Transport is injected in memory; no real network or provider is used. Completion means canonical Document/context creation, not `OutputPlanConfirmed`, generation, an active browser sponsor experience or public beta qualification.

Remaining activation work includes reviewed authenticated entry/host/store wiring, bounded sponsored result/status/download access, approved payer/audience/allowance and launch operations, and explicit schema and route deployment. The other sponsored output/input/provider mappings remain separately qualified scope. No existing marked server plan or native receipt is normalized away to bypass these pending boundaries.
