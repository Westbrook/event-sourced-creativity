# Native retained media custody and qualified bytes

This increment adds private, read-only composition for already supported WAV, sole-file MP4, and selected GLB media. It does not create or activate a share. The identity must come from the actual hosted principal or an independently verified purpose record; calling an exported function with a claimed identity grants no permission.

## Exact existing native boundaries

`retained-story-api.ts` adds only a frozen internal bundle of its existing receipt, current-edit, receipt-predicate, and source-predicate functions. The hosted handlers' existing bytes remain unchanged. The bundle does not simplify their inputs or make their observations authoritative by themselves.

`native-retained-media-custody.ts` captures the complete declared selection and identity before awaiting, reuses actual native principal/history/content readers, invokes the exact appropriate receipt/edit readers, and projects the ordinary native DTO. It preserves current content hash, same Document/artifact/revision, private receipt bytes, previous authored source snapshots, previous private edits, and explicit GLB original-reset lineage. It reexecutes a complete native SELECT after all asynchronous observations. The returned opaque handle privately seals the exact environment, DB, storage binding, configuration, identity, selection, DTO, content, expiry and original signal. Inspection snapshots and SQL assertions are private data, never recipient output or publication permission.

Original Outputs Video remains original-revision-only and uses its existing completed job, slot, immutable planner/provider/input, media and storage-marker guards. Original Outputs GLB uses its actual original native completion witness. Neither path supplies a recovery lease, dispatches, reconciles, settles, or mutates records. Packed original witnesses retain the existing materialized proof structure. Current authored edits and original source provenance remain separate checks; there is no union widening of the text publication authority.

`output-video-retained.ts` preserves ordinary result fields, receipt checks, queries and diagnostics. A private WeakMap retains one owned copy of its already inspected original Video bytes. Its accessor requires the exact returned object, original environment/DB/storage/configuration, captured signal and earliest expiry. Recovery-finalization results receive no byte capability. This capability alone does not recheck its SQL witness; the new native wrapper must do that. Binding checks observe each boundary, not arbitrary mutation and restoration between observations.

## Bounded exact-byte composition

`native-retained-media-bytes.ts` accepts an authentic opaque native custody object. Callers cannot provide a storage key, replacement actor, media URL or SQL predicate. Ordinary media uses one canonical owner-generated-key R2 get; original Outputs Video uses the already-read buffer and never performs a fallback get. The reader requires exact owner, no project-access metadata, MIME, retained SHA-256, current authored length when present, finite size, complete observed stream length, bounded chunk count and full hash. Current authored media checks the actual native request fingerprint and source identity, plus current timing/geometry facts. GLB preserves native format, preview and declared rights/deadline checks.

A single 30-second wall and monotonic budget covers byte retrieval, async inspection, hashing, final SQL and subsequent copies. The original signal races pending get, stream read and final-query operations. Cancellation is best effort without awaiting cancellation completion; even a late R2 get owns and cancels its body. A simultaneous get resolution and abort regression is preserved from independent review. Bounded synchronous parsing is checked before and after; JavaScript synchronous work is not preempted mid-instruction.

The exact requested qualification profile is used: WAV, strict AVC MP4, the separately declared known x264 profile, strict untextured GLB, or the separately declared PNG-textured GLB profile. No broader fallback, stripping, transcoding, new decode dependency or generated replacement is applied. A temporary scale-1 inspection copy may validate authored GLB bounds; it is never stored or delivered. Descriptive metadata qualification does not certify audible/visible/semantic content, inaudible data or covert channels.

Successful qualification attaches unchanged bytes using the existing opaque media adapter. The externally enumerable descriptor contains only a fixed media kind, MIME, hash, byte length and applicable measured dimensions/timing. It contains no private filename, source key/URL, Document/artifact identity, prompt, prose, context, receipt, model policy or input reference. The synchronous object is an observation, not delivery permission. The only byte-copy API executes the complete current native SELECT again and enforces the captured finite budget, environment and signal before returning a fresh buffer. It does not promise continuous observation of storage metadata after the captured read, nor confer sharing, guest, sponsor or financial authority.

The ordinary acquisition buffer, pure gate copy and adapter copy are each bounded by the declared media cap. Original Outputs Video also owns its existing-reader cache and one temporary cache copy. Output copies are explicit; the native wrapper does not perform an extra storage fetch. Unused acquisition copies are zeroed after qualification, while the adapter owns the deliverable copy.

## Supported subset and remaining work

- Text-only 3D and the accepted eight live journeys are not rerun here. Tests use synthetic assets and actual native schemas, parsers, local byte edits, readers and SQL.
- WAV current authored trims and original restores are supported. MP3 remains an implementation gap; frame allocation is not sufficient evidence of bounded entropy consumption, and no decoder/transcoder is introduced.
- Video requires one media-bearing clip matching the native primary file and an immutable retained media hash. Missing legacy hash, multiple independent clips, unsupported container metadata, and original Outputs authored revisions are refused rather than silently selecting another result. The exact native retained Video donor may remain privately readable while its descriptive metadata fails both sharing profiles.
- GLB selects the sole native mesh or exact recorded primary using the existing native selector. Actual scale edits preserve an unreferenced original POSITION accessor/buffer and append scaled geometry. Native custody correctly accepts these derivatives, but the strict sharing gate refuses their unreferenced data. Original restore still qualifies. Supporting those unchanged scaled bytes needs a separately reviewed bounded policy or a clean-byte representation choice; this is an implementation gap, not an explicitly deferred requirement or private-reader defect.
- This increment provides custody and byte observations only. Actor-paid native provenance, personal publication permissions, approval/policy versions, expiry/revocation, lifecycle atomics, selected-share API wiring, asset delivery and client UI remain separate reserved work. Do not bypass those guards with raw helper access, a fake Request, a claimed principal or a pure qualification result.
- Image custody remains the publisher's separate reserved path. No Image/media API, retention runtime, recovery, client, schema or financial path changes are included.

Focused tests and independent evidence cover ordinary DTO parity, original/currents edits/restores, native SQL rejoin, object forgery, copied-buffer isolation, scope/owner/receipt/source retirement, storage/hash/profile refusal, cancellation, finite deadlines, and actual local Workerd/D1 execution with separate strict D1 limits. Exact counts and source seals live in the delivery evidence packet; failed probes remain in that packet with their correction or honest unsupported classification. Publication remains with the established deployment owner after independent final review.
