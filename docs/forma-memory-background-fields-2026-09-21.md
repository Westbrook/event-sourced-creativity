# Pre-authorized private field suggestions — 2026-09-21

## Native implementation

The separately qualified `memory-field-suggestions-v1` recipe uses the existing
suggestion-purpose grant, reference jobs, original-backed history, financial
admission, bounded worker processing, verified accounting and private result
publication. Its distinct `future-originals-actions-and-fields` consent covers
future eligible originals/actions and current saved plain-text fields encountered
in that window. Existing grants are not upgraded. Original, observation-control
and lifecycle profiles are required; English, French, Arabic and Japanese controls
explain the additional source use and separate publication decision.

Native capture rehydrates certified block histories and current placement,
checks current mutation sequence, and binds exact saved text, revision, hash and
supporting event IDs. No unsaved draft is captured. Locked, prohibited, governed,
compound/media and private-generated fields are excluded. At most eight fields,
1,200 code points each, enter one request; provider input contains local field
indices rather than block IDs. Suppressed encounters cannot select a field.
Native action metadata is not sent as independent human preference evidence.

The strict parser requires original-human supporting quotations, exact field
indices, distinct targets, valid language and at most 600 code points per full
replacement. It rejects invented identities, extra write authority, duplicate
JSON keys and unchanged text. Results remain unverified private proposals. The
manifest, inverse dependencies, recertification and user controls include exact
field source history. No eligible original/field pair completes without dispatch
or financial reservation; the existing completion code `no-eligible-originals`
means no original evidence eligible for the selected recipe, not an empty log.

The actual Document editor's **Check saved suggestion** reads the newest bounded
eligible retained proposal without making a model call or creating a Chat turn.
The returned review has a real job identity, not a fabricated specialist execution.
Applying requires explicit approval of the exact job, claim, output hash, locale,
field/version and replacement. Native source/result/access checks join the same
atomic authoring transaction as the event and idempotency receipt. The browser
never supplies replacement text. Lost acknowledgments are unconfirmed, never
permission to repeat an edit or purchase.

Accepted text is authored work with negative Memory-assisted attribution. It is
not enrolled in the disposable private-copy graph. Memory withdrawal preserves
it and native Undo/Redo. Shared public history does not publish supporting Memory
prose or the private job pointer. IME, dirty drafts, navigation, blur, expiry,
privacy mutation and changed native source ownership retire the inline view.

## Exact multiline fields and typed metadata

The actual field endpoint and free request now retain the exact saved value for
the selected block instead of the ordinary assistant's 320-character compressed
excerpt. Newlines, repeated spaces and longer Unicode fields no longer produce a
false stale-field failure. Existing authorization, revision/hash checks and
1,200-character/whole-context byte limits remain mandatory; no draft is sent.

Background capture now accepts ordinary authored plain-text blocks with explicit
subtype, intent, active state and valid nonzero weight. Only the text goes to the
replacement recipe. The existing native authoring transaction preserves these
properties when the user accepts. Protected exclusions, prohibitions, exact text,
governed or unknown metadata, inferred sources, disabled/zero-weight blocks and
media/structured types remain excluded before provider selection.
