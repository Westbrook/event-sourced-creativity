# Replay construction: one context, many outputs

The replay laboratory treats a creative journey as creator-owned evidence, not as an assortment of plausible-looking events. A complete theoretical tour spans all application surfaces; an isolated facet repeats one selected capability without losing its project, document, session, rights, or causal boundaries. Provider-backed actual-data mocks inherit the same structural contract and are checked before an approval is created or a provider is contacted.

## Coherent creator journeys

Each event belongs to a stable project, document, workflow, and causal chain. Separate workflows never complete one another's requests merely because they happen close together or reuse an approved image. Repeated histories preserve unique goal, session, and sharing identities, while nested brief citations, promotion receipts, preview pointers, and original-stream references are rewritten to the actual retained evidence.

The complete tour covers document authoring, all context block types, document views, Library reuse, Canvas synthesis, seven independently lockable focused studies, prompt fans, provider governance, operations, intelligence, the Laboratory, isolated fictional accounts, and expiring read-only consumer delivery. Individual studies remain genuinely isolated rather than disguising a full tour as a deep dive.

## Goals are not finished until a person consumes the result

Goal trajectories are derived from scoped creator declarations and witnessed image or document requests. A durable intent declaration contains an opaque private-content reference and safe lifecycle metadata only; raw statements, nested creative decisions, model prompts, arbitrary metadata, and cross-document references are rejected. Production declarations must use the dedicated private-storage action: the generic event append, batch, and synchronization producer cannot create an intent receipt directly.

An image or artifact completion means the result is **ready**, not that its goal is complete. Only an exact, authorized creator review, save, export, critique, pin, or Library action closes the matching workflow. If a session ends first, the next re-entry can explain the outstanding rights decision, interrupted work, failed request, or ready result after the very first closed session. Optional declarations are not required when the creator explicitly requested the output. Generic inferred suggestions still require the existing multi-session evidence floor, and dismissed, abandoned, foreign, or synthetic goals cannot leak into production recommendations.

## One accepted context, six audiences

A successful nothing-to-something journey formalizes one accepted set of authored decisions, references, locked studies, and exclusions. Every image, short story, scene, presentation, storyboard, and video treatment cites the same project, document, source context, context fingerprint, context revision, and exact source block-version receipt.

Formats carry different titles, audiences, purposes, success criteria, and creator consumption receipts. Presentations retain genuinely distinct slide copy and an accessible PDF export. A previously accepted result can itself become an authored input; the derived result must cite that exact reviewed source block and a new context revision. Provider-backed mocks never claim a paid video render without its own separate approval.

## Reverse reconstruction is hypothetical

The artifact-first form accepts a finished image or any supported document output and infers a possible route from blank canvas to that exact result. Suggested context remains inferred until a creator accepts it; the form exposes confidence, dependency-ordered steps, independent alternative paths, and approval boundaries. The original work is never modified, and optional excerpt text remains component-local rather than entering event payloads, URLs, downloads, provider prompts, or durable storage.

Compatible secondary context is merged before the context is frozen. Contradictory subject, setting, or lighting decisions are rejected. Every unique reference must be ingested and explicitly approved before any shared-context output can proceed; one unresolved reference blocks all six outputs. All seven focused studies become real locked compiler inputs instead of decorative events.

The reconstructed source is polymorphic: submitting a story uses that reviewed story, submitting a presentation uses that presentation, and submitting an image uses that exact reviewed image. Reconstruction never substitutes an unrelated deliverable merely to satisfy a test.

## Trusted sharing and provider safety

Read-only sharing is represented by token-free, document-scoped create and revoke audit receipts from the trusted sharing service. Shares expire within the real one-to-seven-day policy window, revocation is witnessed, and private URLs, redirect targets, arbitrary nested objects, credentials, and public-view telemetry are never invented. These privileged audit event types remain outside the generic user-event producer vocabulary.

Actual-data mocks require explicit one-use creator approval. A bounded, profile-aware structural preflight validates a representative multi-cycle journey before approval persistence, budget reservation, provider planning, or image generation. Later full validation remains in place. Approved image bytes can be reused across fictional outputs without fabricating additional provider calls; licensed references, provider receipts, fictional identities, and synthetic provenance remain attributable and isolated.

Compiler, image-generator, and document-renderer receipts are accepted only from their authorized producers. Scout report-space work must belong to an earlier creator-scoped run with real observation, generation, and cost ceilings; both ordinary completion and budget exhaustion retain matching run-local evidence and actual observed counts. Actual-data video remains a treatment only: every withheld-video receipt must match an earlier human request, come from the renderer, and contain no provider job, provider charge, rendered bytes, or media URL.
