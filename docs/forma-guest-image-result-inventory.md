# Guest Image completed-result inventory

This dormant, read-only increment inventories one retained, completed native
text-only OpenAI Image graph. It does not transfer custody, choose a destination,
read or copy an object, expose private result bodies, create a route, provision
schema, activate a host, or authorize another generation.

The base combines accepted R17 and Guest Image Run Step B with published main417.
The original guest creator/private owner remains distinct from the canonical
payer. Original source, plan, quote, authorization, job, operation slot, grant,
consumption, paired reservations, paid-call receipts and generation identities
are retained. Image uses its native events, two private bodies and acknowledged
PNG descriptor, without an `output_results` row.

## Historical evidence and current custody

The result inventory has a separate opaque identity. It accepts only a complete
native success: completed job, succeeded slot, completed grant, two settled paid
calls, settled paired accounting, one written/acknowledged object and the exact
GenerationCompleted/Usage tail. A completion event left by an interrupted local
terminal operation is insufficient. The existing first-SAVE, preflight-stage,
admission and Run inventories keep their existing boundaries.

Generation policy and payer approval are historical provenance. Their later
revocation, quote expiry, billing-period change or current provider settings do
not renew or invalidate the original purchase. Current guest possession, custody
policy, session, original retained source and both private-body lifetimes still
govern inspection. Historical recording times must still fit the original
execution window. Every retained row and recognized revocation bit is proved
exactly; only recognized production revocation fields are omitted from stable
manifest identity.

A separately named retained-format validator recompiles the recorded Image
release using its own retained definition, interactions, output and copy. Full
canonical equality and original policy/plan hashes bind its opaque value token.
The token confers no execution or custody permission. Shared format, stage and
V3 validation engines preserve existing default current-release behavior for
admission and Run callers. Historical inspection does not relabel an old source
as today's release or skip format validation.

## Bounded inventory and descriptor

The closed versioned manifest binds the source prefix, original native tuple,
settled costs, both private-content hashes and retained object metadata to a
digest of the validated graph. Parsing a manifest never creates an inventory.
The opaque inventory binds the original Request, environment and database, a
nonrenewable 30-second operation deadline and retained-data expiry. Complete
read proofs are rechecked atomically after hashing and before returning it.
The source-free review explicitly reports custody and public reads unavailable.

The object key, recorded SHA-256, MIME, dimensions and publication event are
**recorded descriptors only**. This increment does not call R2, stream an object,
or claim freshly verified bytes. A later finite media operation must prove
actual object ownership, metadata and bounded bytes before any copy or claim.

Closure covers the known owned graph, exact qualified optional schema families,
typed content/event references, Memory associations, scoped durable work,
hold dispositions, managed-video reconciliation and selected shares. Unknown
relevant guest/sponsor/output/Memory families and supported declared dependency
forms fail closed. This is not a global audit of arbitrary unrelated database
tables or JSON. Future governed schema changes need compatibility qualification.

Original event and private bodies are proved exactly. Foreign records are
related through the qualified native owner, stream, Project, Document, resource
and other explicit reference fields. An incidental copied ID or URL in unrelated
prose does not confer custody. The inventory does not parse every unrelated
event, private body, artifact revision or share selection. Known Memory and
Scene reference witnesses retain their own native size and shape limits.

The captured graph, returned rows, bindings and native body sizes are bounded.
Scalar absence checks still depend on database capacity; this does not promise
that every predicate uses an index or that SQL work is constant. The operation
deadline rejects a late result and retires its capability, but does not cancel
an already dispatched D1 query.

## Qualification checkpoint

Independent production and fixture reviews are clear. Native Node/SQLite
qualification has passed two genuine synthetic Image producer/inventory paths
and 125 focused checks across preserved, scoped runs. These cover absent and
three-family Memory, exact optional migration combinations, typed references,
custody and retention, malformed acknowledgements, unchanged original financial
identities, earlier strict inventories and a controlled current-registry advance.
The registry case changes the current compiled definition after genuine original
completion; it is not evidence of a production migration.

Two failures remain in the history: incorrect offline-derived Memory fingerprint
constants were repaired, and an impossible corruption fixture was replaced by a
check of the native trigger that already prevents the duplicate consumption.
The latter failed before inventory inspection. Only affected checks were rerun.
The fixture prohibits mutations, provider access and every storage method during
inspection. Two additional checks passed with Node-hosted production inventory
APIs backed by actual local Miniflare/workerd D1. They exercised 1,957 qualified
read statements, original-result replay and production-approval revocation,
and changed private history. A separate negative control replaced one successful
acknowledgement with null after the complete real proof batch returned; it does
not claim that D1 itself produced that null. Disposable fixture changes
established the negative conditions; inventory inspection remained read-only.

The D1 runs validated every current binding and acknowledgement, using a pinned
cache only for already completed SQL compilation. The offline precheck covered
220 captured schema/query pairs at expression depth 100, compound-select limit
5, 32 function arguments, 100 parameters and 100,000 SQL bytes. Actual inspection
used at most 35 parameters and 21,537 SQL bytes. The local engine separately
accepted five compound terms and refused six. Both disposable engines closed;
these results do not claim deployed worker execution or public activation.

Recorded fixture costs will remain application accounting, not invoices. No
original live-provider journey, real provider charge, financial hold change,
schema activation or deployment is part of this increment. Generated byte
custody, claim/current-custody readers, retirement and public activation remain
subsequent work; the broader server-owned generation architecture stays deferred.
