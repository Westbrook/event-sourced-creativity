# Selected-output sharing — current text scope

This work implements the public data contract and prepare/commit/read/revoke lifecycle for exact current Short story, Scene and Slides outputs, followed by source-only schema/privacy integration and finite recipient/management routes. Qualification uses synthetic local SQLite and frontend fixtures. The actual dispatcher keeps creation closed while metadata-retention approval is pending. No production migration, real share, private-media read or provider call is performed. Whole-Document sharing remains unchanged.

The original mini-app requirement is still open: share only an explicitly selected output, safe title and necessary approved media; exclude private inputs and claim powers; enforce current publishing authority, expiry and revocation. Accepted whole-Document sharing and the completed E/F journeys do not satisfy that distinct requirement.

## Implemented contract

`src/model/selected-output-share.ts` captures a closed output selection: kind, Document ID, artifact ID, exact revision and SHA-256 of the complete retained native JSON. It accepts only the three text kinds and validates their existing native retained DTOs against that exact identity. It refuses Image, Storyboard, Audio, Video and 3D before inspecting the supplied native DTO.

A review candidate contains a separate private selection envelope and `publicOutput`. Only `publicOutput` is intended for eventual recipient delivery. It contains the output kind, reviewed share title, explicit expiry, literal audience content and Forma attribution. Native IDs, content hashes, owner or project identity, retained title, context blocks, source receipts, prompts, notes and private evidence fields are excluded. Slides uses explicit nested public types; even empty citation excerpts and producer fields are omitted. Existing public attribution policy remains in force.

The share title is separately reviewed, nonblank, at most 512 UTF-8 bytes, and excludes C0/C1 control characters. The functional default helper returns the output-kind label; no private Document/project title or filename is inherited. Title text is otherwise preserved. Requested expiry must be a canonical ISO timestamp in the future, no more than seven days from preparation, and no later than actual retained-content expiry. An invalid expiry is refused instead of being silently changed.

The candidate digest covers the complete canonical private review envelope and public payload. Explicit read-share approval has the separate purpose `selected-output-read-v1`, that exact candidate digest and literal `allowPublicRead: true`. This parser verifies data binding only. It does not authenticate a caller-supplied candidate, establish current custody, prove publishing rights or authorize a write.

The closed recipient DTO parser captures plain data descriptors, validates its finite shape and returns a deeply frozen copy. It uses a local placeholder identity only to reuse native structural validation; the placeholder is never a real source lookup, request identity or returned field. Getters, custom prototypes, unknown fields and unsupported shapes are refused. Narrative bodies and Slides display strings remain literal output data. No HTML/Markdown interpretation, linkification, media dependencies or resource fetching is introduced.

Field projection is not semantic redaction. Authored output text, public citation labels, slide theme and footer may themselves contain sensitive words. The creator must review the exact candidate before eventual publication. A safe share title alone does not establish that every output string is safe to publish.

## Native custody and detached lifecycle

`worker/native-retained-text-custody.ts` factors the existing native reader's canonical hosted identity, platform/pilot/consent policy, bounded operational-event snapshot, personal custody, retained bytes and final exact source witness. The ordinary reader uses those same functions; its media and completed-job witnesses remain in `worker/retained-story-api.ts`. The new text proof additionally requires that the principal policy permits unauthenticated public delivery. A policy that permits the authenticated owner only is insufficient.

`worker/selected-output-share-authority.ts` establishes exact completed native job/completion provenance. Its initial scope is original actor-paid personal outputs: ordinary manual Document generation or a succeeded ordinal-zero dynamic output slot with the exact personal plan, completed actor/owner/payer grant, preflight and unredacted explicit authorization envelope. Project/shared, sponsored, workflow, recovery/replacement and unknown provenance fail closed. Current source proof alone is not this provenance proof; client-supplied proof objects and SQL are never accepted. The deadline of any required current pilot cohort also bounds authority and is rechecked after awaited work.

`worker/selected-output-share-lifecycle.ts` derives candidates from fresh native proof, accepts same-origin canonical-principal POSTs for preparation/commit and DELETE for revocation, and has a separate token-only read function. Preparation retains exact selection, separate reviewed title, expiry, candidate digest and issuer/provenance binding; it creates no public token. Commit requires the separate exact-purpose, exact-digest explicit read-share approval. Conditional writes join the exact retained row with current source and provenance proof. Final read joins the complete immutable token row with both proofs after hashing, then synchronously checks deadlines and captured database/environment state before releasing the closed public DTO.

`worker/selected-output-share-schema.ts` is an inert schema constant, mirrored by the unapplied `0040` migration and Drizzle model. Rows contain no output body or plaintext token. A 192-bit random read secret is purpose-hashed before storage. The one-time issue transition cannot be repeated to recover or replace a lost secret: exact replay returns metadata only, and a lost response requires explicit revoke plus a new reviewed intent. Immutable binding, unique-token collision and monotonic-revocation triggers protect those rules even with SQLite replacement conflict policies. No SQL from these constants is installed by runtime initialization. Fresh read-only readiness checks and same-statement schema assertions refuse absent, incomplete or changed schema before issuing or returning a share.

The table also supports one terminal metadata-minimization transition. It revokes access and clears all fourteen private binding fields, including raw owner/email/intent, title, selection, source identifiers and authority hashes. Only share ID, purpose, a purpose-separated owner/intent replay digest, token hash and issuance/revocation/minimization timestamps remain. These operational tombstones prevent token or intent reuse; they are not a claim of anonymous data or full account erasure. Trigger guards reject partial clearing, resurrection and replacement collisions. Preparation consults the replay digest before rereading source content, so erasing private metadata does not make the old intent reusable.

The public read token grants only its selected read scope. Current owner identity comes from the stored issuer plus the actual canonical user row; no owner Request headers are manufactured from a token. Revocation requires fresh canonical same-owner authority but does not require resurrecting an expired or removed source. Requested lifetime is refused if it exceeds source retention, completed-job retention or applicable current authority. No retained public-data copy bypasses source removal, redaction or expiry.

The initial lifecycle is personal, current canonical-principal custody only. Project/shared governance, sponsor preview policy, guests and claim flows remain unsupported. Public release approval is not inferred from export/download acknowledgment or ordinary generation consent. A later edit makes the pinned current-revision share unavailable rather than silently exposing the new revision. Historical snapshot sharing requires separate qualification.

## Finite routes and recipient

The additive dispatcher uses `/api/selected-output-shares` for owned metadata, `/api/selected-output-shares/:id` for deliberate revocation, and `/api/selected-output-shared/:token` for one selected read. It rejects malformed paths, unsupported methods and unexpected queries without falling through to ordinary Document sharing. These routes do not schedule background retention or initialize schema. Missing or partial schema remains unavailable. The owner list returns at most fifty records per page and a bounded cursor; it exposes no raw token, owner identity, source hashes or content, and does not claim current source availability. Revocation and management remain possible after generation consent or source retention ends.

**Creation remains explicitly closed in the actual dispatcher.** `/availability` reports `creationAvailable: false`; `/prepare` and `/commit` refuse before database or source access. A request parameter, installed table, environment value or authenticated principal cannot open this gate. The detached lifecycle remains available only to synthetic qualification; activating creation requires the separately approved and qualified expiry scheduler and a reviewed source change. The runtime patch remains unapplied after automatic approval review rejected it twice; the user has been asked for the required explicit authorization.

`/share/output/:token` uses the isolated public-share entry and a separate recipient. Invalid selected-output paths stay in that namespace and cannot become whole-Document shares. The recipient requests only its exact same-origin read endpoint, uses a bounded closed response parser, displays literal text/Slides fields, and retires content synchronously on expiry, token change or disconnect. It never hydrates the private Store, reads media, linkifies output text or makes provider calls. Locale changes preserve the read and use the saved Forma language. This link remains subject to the site's existing access boundary; current deployment audience is `workspace_all`, not unrestricted external access. Performance summaries redact selected-link tokens, share IDs and metadata query values, and recipient pages remain excluded from telemetry publication.

## Explicit review and current-output wiring

The native mini-app result and current Document artifact viewer now expose a separate Share output surface for Short story, Scene and Slides. Each host supplies the exact current Document, artifact, revision and full retained-JSON hash through a monotonic source lease. The Scene adapter explicitly projects those five fields from its richer native selection; screenplay/body evidence does not become a public selector. No latest-output guess, new private read or provider operation is added. Existing Edit in Forma and Download behavior stays in place.

The publisher starts with an empty title and explicit expiry. Review prepares one exact candidate, renders its closed recipient content, and requires a separate Publish link action. The client validates exact selection, title, expiry, purpose and canonical candidate digest. Host eligibility is only an additional restriction: a server capability read must also permit creation, and the actual dispatcher still reports false. While closed, the surface reports Unavailable and cannot send prepare/commit; existing-link management remains separately available when the installed schema and owner permit it.

Source retirement, owner/route/revision changes, hidden views, close, disconnect and expiry clear candidate content and any one-time token. A retired A→B→A lease cannot resume a prior request. Wall-clock rollback cannot renew the accepted monotonic preview/link deadline. A lost commit response keeps a revoke-only fence in the current surface; it never silently recovers, replaces or retries the secret. Successful revocation resets metadata pagination because the old cursor's row is no longer active. Failed metadata reads report Unavailable and cannot masquerade as an empty link list. User-authored title/expiry controls remain in place across en/fr/ja/ar changes and composition.

## Media and activation still open

The five media modes need integration with their existing native custody/byte witnesses, closed public field allowlists and exact delivered-byte manifests. They do not require another generation or a new ownership system. Owner Storyboard/Video/Audio DTOs contain private production fields. PNG structural inspection currently permits ancillary metadata; a metadata-safe delivery profile or a reviewed, versioned derivative is needed. Full GLB asset validation proves bounded self-contained resources but still permits inert `extras`; it is not semantic redaction. Current native mini-app Video reading refuses edited revisions, so sharing a saved trim needs a separate join between original native provenance and the exact current edit. Do not include sibling outputs, references, input audio, alternative meshes, archives, private scene compositions or saved-view receipts because they share a Document.

The existing confirmed `erase-personal-authored-context` handler now composes optional installed-table revocation and metadata minimization into its atomic batch. It acts even when the separate memory cleanup needs continuation, keeps exact write/terminal acknowledgments, leaves foreign-owner records untouched and preserves `finishedOutputsRetained: true`. A missing selected-share table preserves the prior behavior; an incomplete installation or an unconfirmed write prevents a successful erasure claim. The response separately reports minimized record count and retained operational tombstones. This is the existing personal-context operation, not full account deletion or backup erasure.

The retention helper also prepares one exact revoked-or-expired record cleanup unit and reports remaining work. Its standalone SQLite behavior is qualified; integration into the existing bounded expiry scheduler is a separate pending source change. No additional scheduler, real erasure invocation or production migration has run. Source expiry already prevents public delivery but does not itself erase the stored private link metadata.

Production schema installation, expiry-scheduler integration, opening the creation gate, actual link acceptance, all five media modes and physical-device acceptance remain unfinished. Finite routes, recipient presentation and the explicit publisher/host flow are implemented and synthetically qualified; this does not establish a real published link or public access beyond the current site audience. Only the user's actual explicit publish action creates an audience permission. No real share, new audience permission, source transfer, provider cost or financial hold was created by this increment.

Their fixture enforces D1's 100-binding and 100-KB query limits. Exact pass counts, historical failures and final source hashes are retained in the accompanying validation packet.

The extraction compatibility receipt covers eight existing native reader/completion suites. Its initial missing-import failure remains recorded; after the import repair only the three affected suites were rerun. Distinct latest outcomes pass for all 940 reported cases. The new lifecycle's token replacement issue was found in static review and repaired before its regression checks; it is not represented as a historical failing test. The reproduced post-query cohort-deadline failure is preserved with its targeted repair. These synthetic checks do not qualify deployed route/schema integration, a rendered user interface, real sharing or physical devices.

The schema/privacy follow-up adds actual SQLite tombstone, retention and confirmed-erasure checks, migration parity and preservation tests, plus an actual local workerd/D1 readiness check.
