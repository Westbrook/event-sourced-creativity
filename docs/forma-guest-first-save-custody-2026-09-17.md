This dormant increment covers one native Image request saved after the original guest context prefix. It transfers the context and that saved request to an existing, verified personal account in the same Project and Document. It does not complete generated-result or media custody, grant provider access, install schemas, activate a guest policy, create an account, or register a route.

The deployment owner remains responsible for canonical main and publication. Supplier qualification and root integration review are separate checkpoints.

## Exact supported graph

The original guest stream contains the unchanged N-event context prefix plus exactly one native first SAVE at N+1. The prefix, original plan, original actor, sponsor payer and financial receipts are never rewritten. A genuine opaque inventory validates both-purpose guest credentials, live guest custody policy, retained original plan and every context body, exact original SAVE envelope and resource debit, and the complete native graph. It refuses later confirmation/preflight/generation stages, extra private media, Memory associations and unsupported custody.

The manifest contains immutable source and SAVE commitments. Revoking a production source policy or payer approval does not change this custody identity or strand its lease. Current guest custody policy/session authority and exact retained source remain required for a new claim. Native schema state is qualified and captured as a transaction proof, independently of the manifest digest. Optional sponsor intake-read attempts accept exactly one complete native V1 or V2 family; unknown objects and mixed/partial families are refused.

An existing canonical account obtains a lease using the new typed inventory entry. The original context-only typed lease and abstract dormant lease keep their previous behavior. Cloned/serialized inventories, another DB binding, stale credentials, non-personal contexts and unavailable canonical authority do not authorize transfer.

## Atomic copy and retention

At an existing canonical stream head H, the writer creates the original context prefix at H+1 through H+N and a separate native canonical SAVE at H+N+1. The context receipt remains the existing v1 N-prefix format. The new SAVE has its own canonical actor, command key and native command envelope; an immutable separate mapping preserves the original and target event metadata and private digests without copying private text into the mapping.

All source, destination and lease preconditions must precede event insertion in the same DB batch. The batch also records the exact context receipt and SAVE mapping and revokes the original guest session. A lost or uncertain acknowledgement permits exact completed-receipt recovery, never another mutation attempt. Reads of a completed claim use current canonical authority and immutable receipts, without requiring expired guest credentials.

The original immutable mini-app plan remains the N-prefix plan. Retaining it is an explicit claim operation; GET does not write. A successful coordinator result carrying both a retained private plan and current SAVE availability must finish with one joined current proof. If retention fails after an otherwise completed claim, the result reports that partial state and omits private plan data. Same-Document native editing is available; generation remains unavailable until separately qualified canonical output-plan compilation and admission.

## Separate original-tail cleanup

The new claimed-tail retirement path erases only the original guest SAVE private body when the original source deadline is due. It uses immutable context/SAVE lineage and actual original native association. It does not require a live payer or guest session, and it preserves all original public events, commands, sponsor resource receipts and canonical copies.

Original source retirement and original SAVE-body retirement are separate, idempotent operations. Either ordering must work, including when the original source private bytes have already been erased. Historical metadata cannot reconstruct erased bytes. Canonical edits, native redaction/removal and later unrelated canonical stream events do not renew the original guest retention deadline or authorize erasing canonical data. Missing or changed native target association is refused rather than represented as a tombstone.
