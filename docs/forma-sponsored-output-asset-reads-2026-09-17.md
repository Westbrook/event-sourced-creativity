# Sponsored Image adopted-asset reads

This independently reviewable slice covers `GET /api/output-requirements/assets/:assetId?documentId=...` for the exact native adopted asset of an original sponsored Image. It does not close the whole original-plan consumption requirement.

The route classifies bounded private adoption metadata before native source history is loaded. It joins the retained `asset.origin.jobId`, slot, plan, completion event, source and target contract, then obtains one fresh `image-media` attempt through the existing original Image reader. The final disclosure proof composes that original authority with current adopted-file custody. It does not infer sponsorship from a distinct payer alone.

The exact selected file still uses the ordinary native trusted-context reconstruction, current source checks, adopted-file inspection, storage/hash checks and final atomic disclosure proof under the actual authenticated principal. The complete internal history and source evidence are charged to the same byte budget and absolute monotonic deadline; the response may disclose only the selected file. Another sponsored Document in that principal's stream is not a reason to discard the native reconstruction. The closed DB/R2 adapter refuses unknown queries, preflights scalar byte/type bounds before transferring bodies, rechecks them with the guarded body query, and permits only the selected R2 body plus bounded source metadata checks. A slow or abandoned consumer does not renew the attempt.

Known sponsored whole-Document snapshots and delivery/package downloads return `sponsor_output_selection_required` before private history/file reads and without charging a campaign attempt. A package cannot inherit a one-job allowance. A future mixed snapshot needs an explicit native read-model contract that excludes sponsored resources before body retrieval and exposes their omission; a post-filtered full snapshot is insufficient. This change does not publish such a contract or a campaign activation UI.

Ordinary owned uploads and coherent ordinary native results retain their existing download behavior, including in a Document containing sponsored history. Ordinary Document snapshots and shared-project behavior remain available. Ordinary classification is pinned into the native final proof so a resource cannot change lineage between classification and disclosure. Missing dormant read policy closes the known sponsored read; missing fundamental retained authority or lookup definitions fails closed where classification is uncertain. Generation-grant expiry, disabled generation campaign, and job-status retention expiry do not erase a currently owned completed file's separate native read lifetime.

The sponsored asset branch reads an existing principal and does not run account/profile bootstrap or Outputs schema initialization. Ordinary onboarding keeps its existing lifecycle behavior. The earlier Image/Jobs branches still enter through their preexisting account lifecycle path; their passive-branch guarantee concerns job recovery, reconciliation, settlement, Run and provider dispatch, not a claim that every authentication request is globally mutation-free.

`SPONSOR_OUTPUT_ASSET_READ_INDEXES` exports one dormant exact lookup definition. No initializer, migration, installer, policy approval, financial reservation, provider call, Run or recovery path is added or changed. The read-policy and attempt tables, native Image lookup indexes and this new asset lookup index require a separately reviewed provisioned configuration. Tests provision only disposable synthetic databases and intercepted provider fixtures. App-recorded test amounts are not provider invoices.

Explicitly unclosed: sponsored whole-Document snapshots, multiasset packages, experience-output/event aliases, other output-type sponsored reads, and public campaign activation. The larger server-owned generation architecture remains deferred.

Validation and historical failures are recorded in the accompanying evidence packet; SQLite and local workerd D1 are distinct evidence. No live-provider journey, real download, production data mutation or paid generation was repeated.
